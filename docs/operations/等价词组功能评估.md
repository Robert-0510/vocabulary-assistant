## 3. 核心问题：矫枉过正 —— 义项过度合并

上一轮为修"碎片化"，把义项构建改成"按边聚类"。**代价是重新引入了设计里明令禁止的"连通分量式"合并**（设计总纲 §5.11.5 的反例）。

### 3.1 规模异常

| 成员数 | 义项数 |
|---:|---:|
| 2 | 680 |
| 3 | 91 |
| 4 | 27 |
| 5 | 13 |
| **≥6** | **20**（含 168 个词，占全部词的 9.3%） |

最大的三个：

```text
S0001（14 词）：apropos、experimental、fresh、germane、heterodox、iconoclastic、
                innovative、novel、original、revolutionary、uncharacteristic、
                unexampled、unorthodox、unprecedented

S0002（13 词）：abate、alleviate、curtail、diminish、hamper、impede、mitigate、
                modulate、neutralize、sap、temper、undermine、upend

S0004（11 词）：cryptic、difficult、elusive、enigmatic、evasive、mythical、
                perplexing、significant、sizable、substantial
```

### 3.2 明显非同义的成员

| 义项 | 混进来的词 | 问题 |
|------|-----------|------|
| S0001 | `germane`（相关的）、`heterodox`（异端的）、`experimental`（实验的） | 与 `novel/original`（新颖）不是一回事；14 个词里至少三类意思 |
| S0002 | `hamper/impede/undermine`（阻碍、破坏） | 与 `mitigate/alleviate`（减轻）方向相反 |
| S0004 | `significant/sizable/substantial`（大量的） | 与 `cryptic/enigmatic`（神秘的）毫无关系 |
| S0005 | `uninhabitable`（不能居住） | 混进"虚假、站不住脚" |
| S0012 | `loose`（松散） | 与 `parlous/precarious`（危险）—— 正是设计里那个经典反例 |

### 3.3 对学习体验的直接影响

`equiv_group` 的题干是"选出全部同义替换"。当义项是 S0001 时，用户会被要求把 `germane` 和 `revolutionary` 一起选中才算"全对"：

- 答对不了 → 判 `Again`/`Hard` → 稳定度被打压 → 复习量上升；
- 用户会开始怀疑题目本身；
- 反而让"义项卡"这个设计失去可信度。

**这是当前版本最需要修的一处。**

## 4. 修复建议

| 方案 | 做法 | 成本 | 效果 |
|------|------|------|------|
| A 临时（推荐先做） | 只把 **20 个 ≥6 词的义项**标记 `needs_review`，不建卡；其余 811 个照用 | 10 分钟 | 立刻消除 9.3% 词的错误** |
| B 自动 | 义项规模上限（如 ≤5），超限按词性或桥词再拆 | 半天 | 粗粒度修复，可能拆出新碎片 |
| C 根治 | 每合并一次都做"两两释义校验"：任两词释义不重合则不合并 | 1–2 天 | 需可靠的释义源（当前机经词覆盖 45%） |

**建议 A + C 组合**：现在先用 A 把风险挡住，再用 C 在下一轮重算。B 只在没有释义时兜底。

判据（可加进导入脚本）：义项成员数 ≥6 或"任意两词释义零重合"→ `status='needs_review'`，不生成 sense 卡。
