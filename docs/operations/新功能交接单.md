## 3. P0 数据层

### 3.1 新增 ORM 模型（追加到 `backend/app/models.py`）

```python
STATUS_VALUES = ("new", "learning", "reviewing", "mastered")
PHASE_VALUES = ("new_first", "new_quiz", "review", "relearn", "meaning", "group")
RESULT_VALUES = ("know", "unknown", "master", "correct", "wrong", "partial")


class Sense(Base):
    """义项顶点（二部图右侧）。label_zh 是规范名，不同措辞放 word_senses.gloss_raw。"""
    __tablename__ = "senses"
    __table_args__ = (
        UniqueConstraint("book_id", "label_zh", "pos", name="uq_sense_book_label_pos"),
        Index("ix_sense_book_status", "book_id", "status"),
        {"mysql_charset": "utf8mb4"},
    )
    id: Mapped[int] = mapped_column(BigInteger, primary_key=True, autoincrement=True)
    book_id: Mapped[int] = mapped_column(BigInteger, ForeignKey("word_books.id", ondelete="CASCADE"), nullable=False)
    label_zh: Mapped[str] = mapped_column(String(120), nullable=False)
    definition_en: Mapped[str | None] = mapped_column(String(400))
    pos: Mapped[str] = mapped_column(String(16), nullable=False, default="adj")
    status: Mapped[str] = mapped_column(String(16), nullable=False, default="needs_review")
    merged_into: Mapped[int | None] = mapped_column(BigInteger)

class WordSense(Base):
    """词—义项关联（二部图的边）。"""
    __tablename__ = "word_senses"
    __table_args__ = (
        UniqueConstraint("word_id", "sense_id", name="uq_word_sense"),
        Index("ix_ws_sense_status", "sense_id", "status"),
        Index("ix_ws_word_status", "word_id", "status"),

    book_id: Mapped[int] = mapped_column(BigInteger, nullable=False)
    word_id: Mapped[int] = mapped_column(BigInteger, ForeignKey("words.id", ondelete="CASCADE"), nullable=False)
    sense_id: Mapped[int] = mapped_column(BigInteger, ForeignKey("senses.id", ondelete="CASCADE"), nullable=False)
    gloss_raw: Mapped[str | None] = mapped_column(String(200))
    status: Mapped[str] = mapped_column(String(16), nullable=False, default="active")


class SenseState(Base):
    """义项卡（FSRS），字段与 word_states 完全一致。"""
    __tablename__ = "sense_states"
    __table_args__ = (

        {"mysql_charset": "utf8mb4"},
    )
    id: Mapped[int] = mapped_column(BigInteger, primary_key=True, autoincrement=True)
    sense_id: Mapped[int] = mapped_column(BigInteger, ForeignKey("senses.id", ondelete="CASCADE"), unique=True, nullable=False)
    book_id: Mapped[int] = mapped_column(BigInteger, nullable=False)
    state: Mapped[int] = mapped_column(SmallInteger, default=1, nullable=False)
    step: Mapped[int | None] = mapped_column(SmallInteger)
    stability: Mapped[float | None] = mapped_column(Numeric(12, 4))
    difficulty: Mapped[float | None] = mapped_column(Numeric(12, 4))
    reps: Mapped[int] = mapped_column(Integer, default=0, nullable=False)
    lapses: Mapped[int] = mapped_column(Integer, default=0, nullable=False)
    due: Mapped[datetime | None] = mapped_column(DateTime)
    last_review: Mapped[datetime | None] = mapped_column(DateTime)
    status: Mapped[str] = mapped_column(String(16), default="new", nullable=False)
```

### 3.2 迁移 v4（追加到 `MIGRATIONS`）

现有机制：启动时先 `Base.metadata.create_all()`（会自动建出 models 里新增的表），然后按版本执行未应用的迁移。
所以 **v4 只做两件事**：①兜底建表（幂等，兼容 create_all 未覆盖的情况）；②导入种子数据。

```python
def _sense_graph_migration(conn: Connection) -> None:
    """建义项图三表（幂等）——create_all 通常已建好，这里兜底。"""
    for model in (Sense, WordSense, SenseState):
        model.__table__.create(bind=conn, checkfirst=True)

MIGRATIONS = (
    Migration(2, "...", _fsrs_schema_migration),
    Migration(3, "...", _accounts_migration),
    Migration(4, "bipartite sense graph (senses/word_senses/sense_states)", _sense_graph_migration),
)
```

### 3.3 导入脚本 `scripts/import_sense_graph.py`

输入：`analysis/senses.csv`、`analysis/sense_edges.csv`、`analysis/jjci_words.json`、`docs/audit/2026-11-02-sense-review/review_decisions.json`
目标库：`AppConfig.database_url`

步骤：

1. 找到目标词书（`settings.active_book_id` 或参数 `--book-id`）；**所有词必须先存在于 `words` 表**。
2. 建立"拼写 → word_id"映射：`SELECT id, spelling FROM words WHERE book_id=?`。
3. 遍历 `senses.csv`：
   - `status='review'` 的义项按 `review_decisions.json` 的结论处理：
     - 人工 `合并` → 该义项所有边并入锚词所在的主义项；
     - 人工 `拆分` → 保持拆分（默认）；
   - 写 `senses`（`label_zh` 取锚词释义，无则用锚词拼写；`pos` 用词性推断；`status` = `active` 否则 `needs_review`）。
4. 遍历 `sense_edges.csv`：为每条边（词A、词B）写两条 `word_senses`（A→sense、B→sense），`status='active'`。
5. **只建一次**：脚本启动时若 `SELECT COUNT(*) FROM senses WHERE book_id=?` > 0 则跳过（`--force` 可重建）。
6. 输出统计：义项数、边数、跳过的词（词书里没有的词）。

> 词书里缺词的处置：跳过并记日志，**不要**自动建词（`words` 由词书导入负责）。

## 4. P1 接口层

### 4.1 题型与数据契约

新增两种题（取代旧 `en2cn/cn2en/cloze` 作为复习主题型，旧题型保留为兜底）：

| type | 题干 | 选项 | 正确项 | 写 FSRS |
|------|------|------|--------|---------|
| `meaning_multi` | 英文单词 + 音标 | 4 个义项（单义词）或 `max(5,n+2)` 个（多义词） | 该词全部义项 | 词级卡 `word_states` |
| `equiv_group` | 锚词 + 同题语境 | 义项星成员 + 干扰项 | 星内除锚词外全部 | 义项卡 `sense_states` |

**判分在服务端**：响应不下发 `answer_index(s)`。

```python
class QuizOut(BaseModel):
    type: Literal["meaning_multi", "equiv_group"]
    question: str
    options: list[dict]        # [{"id": int, "text": str}]；id 是 sense_id 或 word_id
    option_count: int
```

### 4.2 `GET /api/study/today` 改造

1. 取到期词（`word_states.due <= now`）+ 到期义项卡（`sense_states.due <= now`）+ 新词。
2. 每个到期义项卡生成一道 `equiv_group`：锚词取该义项下 `deg=1` 的词（叶子优先），选项 = 星内成员 + 2 个干扰词（干扰词必须**不在**同一 sense）。
3. 每个新词/孤立义项词生成 `meaning_multi`。
4. 返回结构在 `TodayOut` 里增加 `sense_items`，字段与 `new_words/review_words` 对齐。

### 4.3 `POST /api/study/answer` 改造

```python
class AnswerIn(BaseModel):
    kind: Literal["word", "sense"]
    target_id: int                    # word_id 或 sense_id
    phase: str
    selected_ids: list[int]           # 选中的选项 id
    response_ms: int | None = None
```

评级映射（**不改 FSRS 算法，只喂不同 input**）：

| 表现 | result | Rating |
|------|--------|--------|
| 全对 | `correct` | Good |
| 部分对（≥1 且不全） | `partial` | **Hard** |
| 全错 | `wrong` | Again |

`phase` 新增 `meaning` / `group`，`RESULT_VALUES` 新增 `partial`，`RESULT_TO_RATING` 增加 `"partial": Rating.Hard`。

### 4.4 义项卡调度

复用 `scheduler.apply_answer`：把 `SenseState` 传进去即可（字段同名）。`derive_status` 逻辑不变。

### 4.5 必测用例（P1）

1. 单义词 → `meaning_multi`，选项数 4，正确项 1。
2. 多义词（如 `manifest` adj/v）→ 选项数 ≥5，正确项 = 该词义项数。
3. 部分正确 → 写 `Hard`，`difficulty` 上升、`reps` 不重置。
4. 干扰项守卫：干扰词不得与正确答案同 sense。
5. 义项卡作答后 `sense_states` 变更，且**被点击的选项词 `word_states` 不变**。
6. 服务端判分：响应里不含正确集合。

## 9. 出问题时先查这里

| 现象 | 原因 | 处理 |
|------|------|------|
| 导入后义项数是 0 | `--book-id` 指错，或词书里没有这些词 | 先确认 `words` 表里有词 |
| 库里出现重复义项 | 导入脚本被跑了两次 | 检查唯一键 `uq_sense_book_label_pos`，脚本应幂等 |
| 义项卡全是 new，从不复习 | `due` 没写 / `sense_states` 没参与 today 查询 | 检查 `today` 的 union 与 `apply_answer` 调用 |
| 前端选项与答案错位 | 服务端判分后仍下发 `answer_index` | 删掉该字段，只回传结果 |
