# 实现大事记（工程实践过程记录）

> **本文是什么**：按时间记录"每个重要功能为什么做、怎么做、怎么验证"，用于工程实践过程留痕与学位论文的"工程实践"章节。

## 0. 项目里原本有哪些"记录"，缺什么

| 类型 | 文件/来源 | 记录了什么 | 缺什么 |
|------|-----------|------------|--------|
| 版本清单 | `CHANGELOG.md` | v1.0.0 的功能点名（21 条） | 只有结果，没有"何时、为何、怎么验证" |
| 设计演进 | `docs/design/项目介绍与方案设计.md` | 方案 A→D 的取舍与冲突清单，带修订日期 | 分散在各章，没有时间轴 |
| 调度专题 | `docs/design/FSRS原理效果与优化清单.md` | FSRS 原理、benchmark 证据、优化清单 | 同上 |
| 数据库演进 | `docs/operations/MIGRATIONS.md` | v1 基线 / v2 FSRS / v3 多账号 | 无日期 |
| 版本控制 | `git log` | 仅 4 个提交（2026-10-22 ~ 11-01） | 提交粒度粗，多数开发未留痕 |
| 数据产物 | `analysis/*.md`、`analysis/*.csv` | 本阶段全部解析与统计结果 | 未纳入项目主文档 |

**结论**：项目有"结果记录"，没有"过程记录"。本文即补这一块。

## 2. 关键决策记录（答辩高频提问点）

| # | 决策 | 放弃了什么 | 依据（可举证） |
|---|------|------------|----------------|
| 1 | 以"真题答案"为第一证据，词表降为辅助 | 只依赖单一 PDF 等价词表 | 两库仅 23.5% 重合；词表 34% 的断言经不起释义检验（§5.11.4） |
| 2 | 二部图（词 + 义项）而非"词—词等价边" | 词对直接连成组 | `loose~parlous` 反例：共享词连通会把"松散"与"危险"焊在一起（§5.11.5） |
| 3 | 等价组 = 义项星，不做连通分量 | 传递闭包合并 | 同上；义项星天然不跨义项 |
| 4 | FSRS 调度单元 = 义项（不是词、不是组） | 一词一卡 / 组级 Leitner | 多义词一词一状态无法区分；组与义项星等价，无需两套（§5.13） |
| 5 | 拆义项：机器只做"词性"硬信号，其余默认合并 | 按释义相似度自动聚类 | 中文二字 Jaccard 太弱，`transitory~ephemeral/temporary` 会被误判为冲突，产生 117 条误报（§5.14.4） |
| 6 | 人工只审高分歧，且可回滚 | 全量人工审核 | 361 个枢纽词 → 26 条（4.7%），人机一致率 96.2% |
| 7 | 词形合并"两边同屈折才合" | 单边自动归原形 | `coveted~covet`、`abstracted~abstract` 会改变词性与词义 |

> 这 7 条是论文"方案论证"与"创新点"部分的骨架：每条都有**被否决的替代方案**和**量化依据**。

- 每完成一个可交付功能，在 §1 追加一行：日期、内容、指标、证据文件。
