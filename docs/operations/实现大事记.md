## 7. 义项判定优先级（2026-11-03 定稿）

二部图的**义项顶点 = 词对的中文释义**，即两个词共享的那个中文意思。取标签的优先级：

| 优先级 | 来源 | 作用 | 覆盖 |
|---|---|---|---|
| 1 | **题目本身（六选二答案）** | 判定"这两个词同义"，是一条义项事实 | 1,150 对（全量） |
| 2 | **《真经 GRE 等价词汇表》行释义** | 行内同义词组直接给出中文释义与分组 | 905 行 / 1,319 词 |
| 3 | **《机经词 7.0》中文释义** | 词典式中文释义，补第 2 级没覆盖的词 | 1,457 词 |
| 4 | **普通词典 + 中文语义相似度**（有道词典、同义/反义关系库） | 前三者都取不到时兜底 | 1,016 词 |

**四个优先级是逐级筛选关系**：一个词或一条词对，如果在优先级高的来源里没有建立起同义关系（取不到中文义项），才进入下一级筛选；四级都建立不起来的，交人工复核。同一内容有多个来源时，以优先级高的为准（例如等价词表与机经释义冲突，取等价词表）。

判定规则（2026-11-03 定稿；**不再使用子串/字面重合判断义项**）：

1. **题库答案是强证据**：词对来自六选二答案，即认定两词同义。只有当枢纽词在中文里是多义词、且各词对的义项在语义上分叉时，才拆成多个义项顶点。
2. **义项相似性按语义判定**：
   - 用《同义关系库》（`data/raw/syn_relations.txt`，228,325 条）判断两个中文义项是否同义（直接同义或共享同义词）；
   - 用《反义关系库》（`data/raw/ant_relations.txt`，15,623 条）判断是否对立，命中即判为不同义项；
   - 两者都查不到关系的，按「不相似」处理（宁可碎片）。
3. **词性是唯一的机器硬信号**：搭档跨词性 → 拆分（§2 决策 5）。
4. 枢纽词在中文里只有一个义项时，它的每条词对都归这个义项（答案优先，不再逐对比字面）。
5. 四级来源都建立不起同义关系时 → 交人工复核。
6. **人工裁决优先级最高**：人工判过的枢纽词记录在 `data/derived/人工裁决.json`，机器规则不得推翻。

明确排除：不使用韦氏词典；不把英文释义作为合并依据。

## 8. 顶点重建与表映射简化（2026-11-03）

### 8.1 重建口径

- **一个枢纽词的等价类 = 一个义项顶点**：A 类全部合并，B 类按语义分组各自成顶点。
- **不做跨枢纽合并**。理由：两个枢纽的星只要共享一条词对就会顺着边连起来，等价于词级传递闭包；实测把 `characteristic` 与 `anomalous` 经 `singular` 连进同一个义项，正是 §2 决策 3 禁止的连带。
- 多义词就是"一个词挂在多个义项上"：`dismiss`、`manifest`、`commonplace` 各挂 5 个义项，符合二部图定义，不需要额外结构。
- 词性冲突是唯一硬否决；人工裁决（37 个枢纽）优先于机器规则。

### 8.2 规模

| 指标 | v4（2026-11-02） | v5（2026-11-03） |
|---|---:|---:|
| 义项顶点 | 1,135 | **857** |
| 边（word_senses） | 2,342 | **2,105** |
| 词汇 | 1,802 | **1,759** |
| 义项规模 | 2 词 761… | 2 词 582、3 词 197、4 词 52、5 词 15、6 词 10、7 词 1 |
| 词所在义项数 | 1 个 1,632、2 个 168 | 1 个 1,500、2 个 188、3 个 57、4 个 12、5 个 2 |

义项比 v4 少 24%：判定从"字面相似"改成"题库答案优先 + 语义相似"，同一组的词更容易合到一起。

**重建时修掉的两个缺陷**（都会直接影响前端题目）：

| 缺陷 | 表现 | 修复 |
|---|---|---|
| 词性守卫把人工合并拆散 | `commonplace` 人工判「合并」，却被拆成 5 个两词义项 | 人工裁决优先于词性守卫（§7 规则 6），只有机器分级才受词性约束 |

## 9. 多义词记忆与等价组简化（2026-11-03）

### 9.1 目标

1. 背单词方式从「认识 / 不认识 / 熟知」切换为**不定项选择释义**；单义词 4 选项（3 错 1 对），多义词选项数 = 正确数 + 2。
2. 等价词组测试独立成功能：先考代表词的背诵，再在选项中选出等价组；**FSRS 只挂代表词**，选项词不写状态。
3. 简化：选项词只考不定项选择；代表词由「单选 + 等价组」共同覆盖；等价组不再单独维护义项卡。

### 9.2 实现口径

| 项 | 规则 |
|---|---|
| 上传拆义项 | 按词性标记（dj./
./. …）切分释义；同书内「释义+词性」相同则复用同一义项，共同释义自然形成等价组 |
| 数据边界 | 等价组只用**精选义项**（\senses.is_curated=1\，来自审核过的等价词图）；上传词书拆出的义项为 0，不形成组题 |
| 代表词 | 义项数 ≤3 且是该组义项最少的成员（单义 → 双义 → 三义）；义项数 >3 的组不出题 |
| 等价组选项 | 组内其它成员为正确项，另加 2 个**多义词**干扰项 |
| 计分 | 代表词的词题是热身（不写 FSRS）；等价组题更新代表词 word_states；非代表词的词题照常计分 |
| 顺序 | 等价组题带 owner_word_id，前端把它排在所属代表词之后 |
| 旧流程 | 自评三键、en2cn/cn2en/cloze、word_id + result 契约全部下线 |
| sense_states | 不再创建/更新；表保留待后续迁移删除 |
