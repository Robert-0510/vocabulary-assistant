## 1. 项目概览

### 1.1 一句话定位

**本地运行的中文背单词工具**：自定义 Markdown 词书 + 每日任务 + FSRS 间隔重复 + 多账号数据隔离；数据保存在自己的 MySQL 中，不依赖云账号。

### 1.2 目标用户与场景

- 备考 GRE / 雅思 / 考研 / 托福，需要导入自己的词书，而不是接受平台内置词库。
- 重视数据自主与隐私，希望学习记录只留在本机。
- 需要一个能长期维护、可解释、可测试的本地工具，而不是黑盒算法产品。

### 1.3 设计目标

1. **数据自主**：账号、词书、记忆状态、流水都在本机 MySQL；导出即完整备份。
2. **调度可解释**：使用 FSRS 的标准字段与评分映射，避免自创不可验证的算法。
3. **低运行成本**：单进程 FastAPI + 本机 MySQL；不依赖消息队列、缓存、对象存储。
4. **可增量演进**：数据库迁移版本化，旧库可升级，新功能不破坏既有数据。
5. **可测试**：后端 pytest、前端 Vitest、CI 覆盖关键链路；算法与接口都可单测。

### 1.4 非目标（明确不做）

- 不做云同步、云账号、多端实时同步。
- 不做在线词典/在线同义词库的自动抓取（隐私与版权双重限制）。
- 不做移动原生 App；当前只有 Web 与 Windows 打包。
- 不做多租户 SaaS、社交、排行榜、付费体系。
- 不做自动更新；发布以 exe/源码包为主。

## 2. 系统架构

### 2.1 总体架构

```text
浏览器（Vue SPA）
  ├─ 页面/组件/键盘交互
  ├─ Axios（Cookie 会话）──► FastAPI
  │                           ├─ 鉴权依赖（Cookie → 用户）
  │                           ├─ 业务路由（auth/books/study/stats/settings/backup）
  │                           ├─ 服务层（md_parser/FSRS/rate_limit）
  │                           └─ SQLAlchemy ──► MySQL 8（本机）
  ├─ Web Speech API（TTS）
  └─ 有道发音音频（仅兜底，浏览器直连）
```

### 2.2 请求与鉴权链路

1. 浏览器携带 `va_session` HttpOnly Cookie。
2. `get_current_user` 取 Cookie token 的 SHA-256，查 `user_sessions`，校验过期。
3. 业务路由通过 `user.id` 过滤数据；跨账号资源统一 404，不泄露存在性。
4. 中间件记录 `X-Request-ID`、方法、路径、状态码、耗时。
5. 登录/注册/改密有限流；上传/导入有大小与数量上限。
6. 生产同源托管前端，禁用 CORS；开发模式只允许本机 Vite 地址。

### 2.3 关键数据流

- **上传**：multipart → 解析 Markdown → 生成词书名/单词列表 → 去重与截断 → 写 `word_books/words/word_states` → 首次上传自动设为当前词书。
- **今日任务**：读 `settings.active_book_id` → 预取候选池 → 复习池（到期）+ 新词池（`stability IS NULL`）→ 生成题目 → 返回 `new_words/review_words`。
- **作答**：`word_id + phase + result` → 校验归属 → FSRS 更新 `word_states` → 写 `study_logs` → 返回新状态/到期日。
- **统计**：按 `user_id + studied_at` 聚合流水；按 `word_states.status` 统计分布。
- **备份**：按账号导出 JSON；导入为合并模式，同名词书自动改名。

### 2.4 部署与配置

- 打包版：exe 启动 uvicorn，静态托管 `frontend/dist`，浏览器打开 `http://127.0.0.1:8000`。
- 配置文件：源码用 `backend/.env`；打包用 `%APPDATA%\背单词助手\.env`；可用 `VOCAB_ENV_FILE` 指定。
- 关键配置：`DB_*`、`COOKIE_SECURE`、`SESSION_TTL_DAYS`、`MAX_UPLOAD_MB`、`MAX_IMPORT_MB`、`MAX_WORDS_PER_BOOK`、`RATE_LIMIT_ENABLED`、`LOGIN/REGISTER/PASSWORD_RATE_LIMIT`。
- 数据库账号建议使用 `scripts/setup_mysql.sql` 创建的最小权限账号，不用 root 日常运行。

## 3. 数据模型

### 3.1 现有表

| 表 | 关键字段 | 约束/索引 | 作用 |
|----|----------|-----------|------|
| `users` | id, username, password_hash, created_at | username UNIQUE | 账号 |
| `user_sessions` | token_hash PK, user_id, expires_at | user/expires 索引 | 会话（只存 token SHA-256） |
| `word_books` | id, user_id, name, description, word_count | UNIQUE(user_id, name) | 词书 |
| `words` | id, book_id, spelling, phonetic, definition, example_en/cn, seq | UNIQUE(book_id, spelling) | 单词/短语 |
| `word_states` | word_id UNIQUE, book_id, state, step, stability, difficulty, reps, lapses, due, last_review, status | book/status、due、stability 索引 | 每词一条 FSRS 状态 |
| `study_logs` | id, user_id, word_id, phase, result, studied_at | user+studied_at、word 索引 | 学习流水 |
| `settings` | user_id PK, new_per_day, review_per_day, active_book_id | active_book_id SET NULL | 每账号设置 |
| `schema_migrations` | version PK, description, applied_at | — | 迁移记录 |

### 3.2 关系与归属

```text
users 1─n word_books 1─n words 1─1 word_states
  │                     └─n study_logs（user_id + word_id）
  ├─1 settings（active_book_id → word_books, ON DELETE SET NULL）
  └─n user_sessions
```

- 词书、设置、流水直接带 `user_id`；`word_states` 通过 `book_id → word_books.user_id` 间接归属。
- 删除词书级联删除 words/word_states/study_logs；删除账号级联删除全部数据。
- 删除当前词书时自动回退到剩余最近创建的一本；没有剩余则 `active_book_id = NULL`。
- 跨账号访问统一 404。

### 3.3 FSRS 状态语义

| 字段 | 含义 |
|------|------|
| `state` | 1=Learning，2=Review，3=Relearning |
| `step` | 学习/重学步进索引；Review 为 NULL |
| `stability` | 记忆稳定性（天）；NULL = 尚未学习的新词 |
| `difficulty` | 记忆难度（约 1–10） |
| `due` | 下次到期时间；UTC naive（MySQL DATETIME） |
| `last_review` | 上次复习时间；UTC naive |
| `reps` | 连续答对次数；Again 时重置 |
| `lapses` | 遗忘次数 |
| `status` | 派生 UI 状态：new / learning / reviewing / mastered |

- 评分映射：不认识/答错 → Again；认识/答对 → Good；熟知 → Easy；Hard 暂不使用。
- 学习/重学步进设为 1 分钟，保证答错卡当日由前端队列重学，答对毕业。
- `stability ≥ 90` 视为“已掌握”，仍按到期时间抽查。
- 时间约定：`due/last_review` 存 UTC naive；比较用 `utcnow_naive()`；展示用本地日期。

### 3.4 迁移与基线

| 版本 | 内容 | 数据影响 |
|------|------|----------|
| 1 | 基线（最初 `create_all`） | 否 |
| 2 | SM-2 列 → FSRS 列 | **破坏性**：清空词书/单词/状态/流水 |
| 3 | 引入多账号：补 `user_id`、重建 `settings` | **破坏性**：清空无主数据 |
| 4 | **规划（已定稿）**：二部图表 `senses` / `word_senses` / `equivalence_candidates` / `sense_ledger`（§5.11.2）+ 真题表 `exam_sessions` / `exam_items` / `exam_item_options`（§5.12.5） | 增量，不破坏既有数据 |

规则：

- 结构变更必须在 `MIGRATIONS` 末尾追加版本，**不修改已发布迁移**。
- 全新库：`create_all` 按当前模型建表，然后盖章基线及历史迁移，不执行破坏性 DELETE。
- 旧库：按版本顺序执行未应用迁移。
- MySQL DDL 隐式提交，迁移非完全事务性；升级前备份。
- 迁移实现要 inspect 后按需建表/加列/加索引，保证可重复执行。

### 3.5 备份格式

- 格式标记：`format: "vocab-assistant-backup"`，当前 `version: 1`。
- 内容：词书、单词、FSRS 状态、学习流水、每日设置、当前词书名。
- 导入为**合并**：同名词书改名为 `名称(2)`；不覆盖现有数据。
- 限制：默认 50 MB；校验格式/版本/词书数/单词数/流水数；非法文件 4xx。
- **v2 规划**：加入等价词组定义、组成员、组状态；`synonym_events` 可选（默认不导出，避免备份过大）。旧 v1 备份仍可导入；新版本导入需同时接受 v1/v2。
- 备份含个人学习数据；若包含第三方词表定义，提醒用户不要公开分享。

### 3.7 数据设计原则

- 调度单位是“词”，组练习是“额外的关系层”；**不把组做成 FSRS 卡**。
- 组状态与词状态分离，避免一次点击同时改写两类记忆。
- 能用冗余 `book_id` 降低高频查询成本的，保持与 `word_states` 一致的做法。
- 不做软删除；删除即物理删除并级联。
- 结构变更增量、可回滚（通过备份），不重写历史迁移。

## 4. 核心学习流程

> **2026-11-01 提示**：本章描述的是 **v1.0.0 现状**（自评三键 + 四选一）。
> 方案 D（§5.10）会取代 §4.2 的自评分支、§4.3 的题型表与 §4.4 的评级映射；每日任务生成（§4.1）、统计口径（§4.5）、边界处理（§4.6）继续有效。

### 4.1 每日任务生成

1. 校验 `settings.active_book_id` 存在且属于当前用户；否则 400（无词书/词书不存在）。
2. 一次预取本书的拼写/释义候选池，避免每题查库。
3. **复习池**：`stability IS NOT NULL AND due <= now`，按 `due` 升序、`lapses` 降序，取 `review_per_day`。
4. **新词池**：`stability IS NULL`，按 `seq` 升序，取 `new_per_day`。
5. 为每个词生成题目：新词用 `cloze`（有例句时），复习词随机 `en2cn/cn2en`。
6. 返回 `new_words/review_words` 与 `new_target/review_target`。
7. 无任务时返回空列表，前端显示“今日没有待学习任务”，而不是错误。

### 4.2 会话队列（前端状态机）

```text
新词：intro（认识/不认识/熟知）
        ├─ 认识/熟知 → detail（释义/例句）→ 下一个
        └─ 不认识   → detail → quiz（挖空）→ 答对 → 队尾 recheck → 出队
复习：quiz（看英选中/看中选英）
        ├─ 答对 → 出队（新词会追加一次 recheck）
        └─ 答错 → detail（正确答案）→ 克隆回队尾重学
```

- 新词:复习 ≈ 1:2 交替出牌。
- `recheck` 不重复提交 FSRS；只在首次测试时更新状态。
- `graduate` 计数只对首次出现的项生效，克隆项不重复计数。
- 进度条按“已毕业/总项”计算；今日进度另按流水去重统计。

### 4.3 题型与选项

| 题型 | 题干 | 选项 | 生成规则 |
|------|------|------|----------|
| `en2cn` | 英文单词 | 4 个中文释义 | 正确释义 + 同书 3 个随机干扰项 |
| `cn2en` | 中文释义 | 4 个英文单词 | 正确拼写 + 同书 3 个随机干扰项 |
| `cloze` | 例句挖空 | 4 个英文单词 | 正确拼写 + 3 个干扰项；例句中找不到词形时退化为 en2cn |

- 选项去重（大小写不敏感）；正确答案始终包含。
- 干扰项从同词书随机取；候选池一次预取，避免 N+1。
- 未来可加入“近义干扰项”，但必须过“义项守卫”：若候选干扰项的释义与正确项释义有交集（按 `；;，,、/` 切分的义项有重叠），则不使用该干扰项，避免一题多解。

### 4.4 作答与 FSRS 更新

| 交互 | phase | result | FSRS Rating |
|------|-------|--------|-------------|
| 新词首见“认识” | new_first | know | Good |
| 新词首见“不认识” | new_first | unknown | Again |
| 新词首见“熟知” | new_first | master | Easy |
| 新词挖空答对 | new_quiz | correct | Good |
| 新词挖空答错 | new_quiz | wrong | Again |
| 复习答对 | review | correct | Good |
| 复习答错 | review | wrong | Again |
| 重学答对/答错 | relearn | correct/wrong | Good/Again |

- `apply_answer` 由 FSRS 计算新 `state/step/stability/difficulty/due/last_review`，再派生 `status`。
- Again：`lapses+1`、`reps=0`；Good/Easy：`reps+1`。
- 每次作答写 `study_logs`；同一词当日多次作答按流水保留，统计去重。

### 4.5 统计口径

- 总览：总词数、各状态数、连续打卡、累计天数、今日已学。
- 日历：按 `studied_at` 的本地日期聚合，返回每日学习词数（去重）。
- 近 30 天：按 phase 区分新学/复习。
- 状态分布：`word_states.status` 计数。
- 今日进度：按当日流水的 word_id 去重；`new_first/new_quiz` 计新词，`review/relearn` 计复习。

### 4.6 边界与错误处理

- 无当前词书 / 词书不存在：400 + 明确文案；前端引导去词书页。
- 词书为空 / 今日无任务：空状态，不是错误。
- 服务异常：错误页 + 重试，不伪装成“今日已完成”。
- 上传超限：413；解析不到有效词：400；字段超长：安全截断。
- 导入非法 JSON/版本/数量：400/422，整体回滚。
- 限流：429 + `Retry-After`（进程内，单进程有效）。

### 5.2 数据事实：这份 GRE 等价词表到底是什么

数据来源：`D:\study_material\GRE\张巍资料\真经GRE等价词汇总（2026年版）.pdf`（本地文件，未随仓库分发）。PDF 第 5–29 页（印刷页码 1–25）共 905 行，5 天任务。

| 指标 | 数值 | 说明 |
|------|------|------|
| 行数（组数） | 905 | 每行一个 headword，headword 不重复 |
| 唯一单词数 | 1,318 | 含词与短语 |
| 单词提及次数 | 2,150 | 头词 + 近义词 |
| 组大小 | 668 组 2 词、165 组 3 词、49 组 4 词、16 组 5 词、6 组 6 词、1 组 7 词 | 73.8% 是二元组 |
| 唯一无序近义对 | 895 | 去重后 |
| 重复近义对 | 350 / 895（39.1%） | 含互逆对与多行重复 |
| 与其他行共享单词的行 | 700 / 905（77.3%） | 组高度重叠 |
| 只做近义词、未做头词的词 | 413 / 1,318（31.3%） | 无行级中文释义 |
| 跨多个中文释义的词 | 544 / 1,318（41.3%） | 部分是近义表述，部分是真正的多义 |
| 按中文释义合并的组 | 767 | 515 组 2 词、132 组 3 词……最大 11 词 |
| 被多行共用的中文释义 | 101 | 如“异常”“短暂”“支持”“贬低” |
| 连通分量 | 470 | 最大 20 词，会把反义/不同词性拉在一起 |
| 短语头词 / 短语近义词 | 14 / 20 | 如 `insulated from`、`buffered against` |
| 编号多义行 | 至少 6 | 如 `obscure`、`sanction`、`inimical` |
| 数据量 | 25 个数据页 / 5 天 | 平均约 181 行/天 |

**关键结论：**

1. 这是“行级等价关系”，不是“互斥的近义组”。中文释义描述 headword，不保证每个近义词都同义。
2. 组与组高度重叠；同一词、同一对词会重复出现。
3. 31% 的词只做近义词，没有自己的释义，不能直接当代表词。
4. 41% 的词跨多个释义；一个 `word_states` 行无法表达多义。
5. 73.8% 的组只有 2 词；“漏选”空间很薄，多选主要发生在大组。
6. 存在词性错位、松散等价、自相矛盾的释义；不能把“非近义词”一律判错。
7. 连通分量会把反义/不同词性合并（如 `mitigate` 分量包含 `block`，`caustic` 分量混入名词/动词），不能当组用。

PDF 第 2 页原文也明确说：**“等价词不一定是完全的同义词……一定要在原题的语义环境中进行等价词的正确理解。”**

典型反例：

| 现象 | 例子 | 设计影响 |
|------|------|----------|
| 互逆/重复对 | `anomaly ↔ aberration`、`aberration → anomaly`、`irregularity → anomaly` | 同一关系被多次测试 |
| 行内多义 | `obscure → anonymous, opaque, obfuscate`，释义“不出名/费解/使费解” | 三个近义词对应三个义项，不能混组 |
| 释义自相矛盾 | `sanction → endorse, countenance`，释义“制裁，批准” | 按释义分组会把反义义项放一起 |
| 词性错位 | `indifferent → apathy`、`vitriolic → opprobrium` | 点击“正确近义词”也不等于能互换 |
| 松散等价 | `general → abstract` | 用“中文意思相同”硬判会误伤 |
| 组名噪声 | 按“支持”合并出现 `authorize/sanction/commend` | 自动合并会制造错误组 |
| 组名噪声 | 按“多才多艺”合并出现 `capricious/erratic/fickle` | 同一词的多义被混在一起 |
| 重复项 | `rudimentary` 的 `sketchy` 同一行出现两次 | 选项必须去重 |

### 5.3 原方案验证：保留什么、修正什么

用户原方案的 4 条规则，逐条结论如下。

#### 规则 1：每组选一个代表词，先自评“认识/不认识”

**保留：** 代表词作为组入口、先自评再决定是否辨析、组内共享释义的教学顺序。

**冲突：**

1. “组”未定义：PDF 行 905 组、按释义 767 组、按连通分量 470 组，成员和难度完全不同。
2. 规则 4 说熟知词不做代表 → 代表更容易落在不熟词上 → 规则 1 的“不认识”分支更容易触发 → 近义词选择被绕过。
3. 代表词与选项词的状态更新口径不一致：代表词来自自评，选项词来自点击，两套证据混用。

**修正：** 行级组；默认 headword 当代表；代表词自评单独事件；不熟代表也允许“预览同组词”（不计分）。

#### 规则 2：每点一张卡，绿=认识、红=不认识

**保留：** 混合真/假选项的辨别练习；逐卡即时反馈用于练习阶段。

**冲突：**

1. “认出它是近义词”≠“认识这个词的释义”，会给未学过的词虚增 FSRS 稳定性。
2. 点错一个“非近义词”也不等于“不认识这个词”（可能是熟悉的词，只是在本义项下不是近义词）。
3. 即时绿/红泄漏答案，选项少时变成“点到变绿为止”。
4. 一次会话按点击批量更新多个词的 FSRS，证据密度太低。

**修正：** 选项点击只写 `synonym_events`，不写 FSRS；练习模式保留即时反馈，测试模式“先多选、后确定”。

#### 规则 3：“确定”后展示漏选，并把漏选词记为“不认识”

**保留：** 明确提交点；提交后展示漏选；漏选进入下一次复习闭环。

**冲突：**

1. 漏选可能是没看见、不确定、时间不够、分页未展示；一律记“不认识”会产生假阴性。
2. 熟知词做选项且被漏选时，会被打回重学，违反规则 4 的初衷。
3. 只有“所有真近义词都展示”时漏选才有定义；分页/采样时不公平。
4. 没有“不确定/跳过”状态，用户会风险规避，反而漏更多。

**修正：** 漏选只记 `missed` 事件；增加“不确定”；只有本轮展示过的真近义词才计漏选；熟知词漏选只显示“未选”。

#### 规则 4：每个词都能当代表；熟知词只做选项；选项优先不熟词

**保留：** 覆盖更多词、熟知词做近义干扰、不熟词优先。

**冲突：**

1. 在这份 PDF 里，413 个词没有自己的释义，不能当代表；强行当代表只能借用别行释义。
2. 多义词一个状态不够；同一个词在 A 组“认识”、B 组可能“不认识”。
3. 熟知词做选项会被反复点击/漏选，产生额外事件，挤占不熟词机会。
4. hub 词（`capricious` 8 行、`volatile/impair` 6 行、`mitigate` 5 行）会被过度使用。

**修正：** 代表词候选 = 有独立释义且与组释义匹配的词；默认 headword；熟知词只做选项且不更新状态；hub 词每天限 2–3 组。

### 5.5 关键设计决策

#### 5.5.1 组单位：PDF 行级组，不做自动闭包

- 每行保留 `headword + 近义词 + 中文释义 + 页码/天`；可追溯。
- 互逆对/重复对用 `group_key` 归并，保留来源行。
- 多义行（至少 6 行）按义项拆 `sense`；近义词按人工/词性/语义匹配分配；不能确定的标 `needs_review`。
- 不自动按中文释义合并全部组；若合并，只对 101 个多行共用释义做人工确认，并要求“成员两两可解释”。
- 组大小 2–7 词；7 词组用 3×3 网格；超过 7 才拆轮。
- 状态：`active / needs_review / retired`；只有 `active` 进每日计划。

#### 5.5.2 状态分离：词义、组关系、事件三层

| 层 | 载体 | 回答的问题 | 谁更新 |
|----|------|------------|--------|
| 词义 | `word_states`（FSRS） | “这个词的释义记住没有？” | 代表词自评、原有每日测验 |
| 组关系 | `synonym_group_states` | “这组近义关系分清没有？” | 组提交（对/错/漏选） |
| 事件 | `synonym_events` | “这次发生了什么？” | 每次点击/自评/提交 |

一句话：**FSRS 只回答词义，组状态只回答关系，事件只做证据。**

#### 5.5.3 代表词选择

```text
候选 = 组内成员 ∩ 当前词书有 word_id 的词
若 候选 < 2 → 跳过该组（覆盖不足）
优先：
  1. 不是用户明确标记“熟知/已掌握”的词（全部熟知 → 退役该组）
  2. 词义稳定性最低 / lapses 最高
  3. 最近最少被选为代表的词
  4. 不是当天已被 2 个以上组使用的 hub 词
轮换：同一组内不连续两次用同一个代表
```

- 默认代表：`role='head'` 且 `word_id` 有释义的词。
- 近义词当代表的条件：有 `word_id`、有独立释义、与组释义匹配（人工审核或词书释义校验）。
- 代表词“不认识”：展示释义 + 例句/发音 → “看看同组词”（预览，不计分）→ 下一个。
- 全部成员已掌握：退役该组，不再安排。

#### 5.5.4 选项生成

- 真选项：组内除代表词外的**全部**成员（通常 1–6 个）。
- 干扰项 2–4 个，从当前词书取，排除：
  - 本组词；
  - 与代表词语义重叠的词；
  - 同一义项的近义词；
  - 本轮已出现的词。
- 总卡片 4–9 个；7 词组用 3×3 或可滚动网格；小词书不足时减少卡片。
- 二元组：可做“是/不是”题，或补 3 个干扰项做 4 选 1。
- 选项随机，真/假交错。

#### 5.5.5 交互：练习模式 vs 测试模式

| 模式 | 反馈 | 计分 | 写 FSRS | 用途 |
|------|------|------|---------|------|
| 练习模式 | 点一张立刻绿/红 | 否 | 否 | 初次接触、热身 |
| 测试模式 | 多选后“确定”，统一显示 | 是 | 仅代表词 | 每日组任务、到期复习 |

测试模式流程：

```text
代表词
  ├─ 认识 → 混合选项（多选，不即时变色）
  │         → 确定 → 绿/红/灰/黄 + 漏选 → 组评分 → 下一组
  └─ 不认识 → 释义 + 例句/发音
              → [看看同组词]（预览，不计分）
              → [标记不熟] / [下一组]
```

- 测试模式不要即时绿/红；否则变成试错。
- “不确定”用黄色，不计对错；提交后展示。
- 漏选只统计本轮展示过的真近义词；显示“漏选：…”；可“再试一次”（练习，不计分）。
- 熟知词漏选只显示“未选”，不显示“不认识”。
- 颜色之外用图标/文字（✓/✗/?），避免只靠红绿。

#### 5.5.6 调度

- **独立模块**：仪表盘加“等价词组”入口；10–20 组/天；不挤占 25 词/天新词计划。
- **组调度**：简单 Leitner，不套 FSRS：
  - 首次 1 天后；
  - 正确率 ≥ 80%：2 → 4 → 7 → 15 → 30 天；
  - 正确率 < 60%：回 1 天；
  - 手动“标记不熟”：回 1 天。
- **due**：`next_due <= now`，或组内有成员词到期（只作建议，不改 `word_states.due`）。
- **冷却**：同组 3 天内不重复；hub 词每天最多 2–3 组。
- **覆盖**：只排“当前词书 ≥ 2 个成员”的组；显示“可用组 X / 总组 Y”。
- **示例**：25 个单词 + 10 个等价词组 ≈ 15–20 分钟。

#### 5.5.7 混淆对与冷却（P3，借鉴 WordWise）

- 用户把 A 误选成 B（B 不在 A 的组内）时，记 `(A, B)`，只写事件。
- 风险分：`risk = 100 × (0.45×repetition + 0.30×recency + 0.15×incorrectness + 0.10×hesitation)`；其中 `repetition=min(1,wrong_count/3)`、`recency=exp(-days_since_last/14)`、`incorrectness=wrong_count/attempts`、`hesitation=min(1,avg_response_ms/30000)`；`wrong_count ≥ 2 && risk ≥ 40` 才展示。
- 同一对词 15 分钟内不再出现；易混对反向影响组排序。
- 目的：把“点错”变成可解释的复习信号，而不是直接扣 FSRS。

### 5.6 数据模型（迁移 v4 规划）

```sql
CREATE TABLE synonym_groups (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  user_id       BIGINT NOT NULL,
  group_key     CHAR(64) NOT NULL,          -- hash(gloss + sorted term_keys)
  title         VARCHAR(100) NOT NULL,      -- 组名，如“缓和”
  gloss         VARCHAR(200) NOT NULL,      -- 中文释义/辨析
  source        VARCHAR(32) NOT NULL DEFAULT 'gre_equiv_2026',
  source_ref    VARCHAR(64) NULL,           -- 页码/天/行号
  status        VARCHAR(16) NOT NULL DEFAULT 'active',
  created_at    DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uq_group_user_key (user_id, group_key),
  KEY ix_group_user_status (user_id, status)
);

CREATE TABLE synonym_group_members (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  group_id      BIGINT NOT NULL,
  term          VARCHAR(100) NOT NULL,
  term_key      VARCHAR(100) NOT NULL,      -- lower(trim(term))
  role          VARCHAR(16) NOT NULL DEFAULT 'synonym', -- head/synonym
  sense_index   SMALLINT NULL,
  word_id       BIGINT NULL,                -- 关联当前词书词；可空
  position      INT NOT NULL DEFAULT 0,
  UNIQUE KEY uq_member_group_term (group_id, term_key),
  KEY ix_member_word (word_id),
  FOREIGN KEY (group_id) REFERENCES synonym_groups(id) ON DELETE CASCADE,
  FOREIGN KEY (word_id) REFERENCES words(id) ON DELETE SET NULL
);

CREATE TABLE synonym_group_states (
  user_id       BIGINT NOT NULL,
  group_id      BIGINT NOT NULL,
  reps          INT NOT NULL DEFAULT 0,
  lapses        INT NOT NULL DEFAULT 0,
  streak        INT NOT NULL DEFAULT 0,
  accuracy      DECIMAL(5,2) NULL,
  last_seen     DATETIME NULL,
  next_due      DATETIME NULL,
  last_rep_word_id BIGINT NULL,
  PRIMARY KEY (user_id, group_id),
  KEY ix_group_state_due (user_id, next_due)
);

CREATE TABLE synonym_events (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  user_id       BIGINT NOT NULL,
  group_id      BIGINT NOT NULL,
  word_id       BIGINT NULL,
  term_key      VARCHAR(100) NOT NULL,
  event         VARCHAR(24) NOT NULL,       -- rep_known/rep_unknown/option_correct/option_wrong/option_uncertain/missed/session_submit
  first_attempt TINYINT(1) NOT NULL DEFAULT 1,
  response_ms   INT NULL,
  created_at    DATETIME DEFAULT CURRENT_TIMESTAMP,
  KEY ix_ev_group_time (user_id, group_id, created_at),
  KEY ix_ev_word (word_id, created_at)
);
```

可选的词条近义表（沿用旧方案中仍然有效的部分）：

```sql
CREATE TABLE word_synonyms (
  id             BIGINT PRIMARY KEY AUTO_INCREMENT,
  word_id        BIGINT NOT NULL,
  book_id        BIGINT NOT NULL,
  term           VARCHAR(100) NOT NULL,
  term_key       VARCHAR(100) NOT NULL,

```

说明：

- `synonym_groups` 是组练习的来源；`word_synonyms` 是词条标注，两者不要混用。
- 词卡展示可合并两边并去重；组状态只挂 `synonym_groups`。
- `group_key` 用稳定哈希，重新导入时 upsert，保留组状态。
- `word_id` 可空：词书没有该词时标记 external，只展示/做干扰项，不更新状态。

### 5.7 状态更新规则

| 用户动作 | `word_states`（FSRS） | `synonym_group_states` | `synonym_events` |
|----------|------------------------|------------------------|------------------|
| 代表词选“认识” | 仅当代表词释义与组释义匹配：Good | 开始会话 | `rep_known` |

### 5.8 与旧方案的关系：保留、修订、废弃

**保留：**

- 词条近义词展示与辨析说明（`word_synonyms`）。
- 近义干扰项（作为普通题型的可选增强，需过义项守卫）。
- 混淆风险分 + 冷却（WordWise 思路）。
- 输入式判分阶梯（P4 可选）：
  - L0 精确：`NFKC` + 去词性前缀 + 去空白/标点 + 小写后，与释义全等；
  - L1 义项：释义按 `；;，,、/` 切项，与任一项全等；
  - L2 近义词表：命中该词已关联的显式近义词 `term_key`；
  - L3 用户确认：界面显示“算我对”，确认后写入 `word_synonyms(source='accepted')`；
  - L4 语义模型：默认关闭，只做兜底，必须用户确认后才生效。
- 备份版本化、迁移幂等、N+1 治理等工程原则。

**修订：**

- 组单位从“每行直接当互斥组”改为“行级组 + 去重/多义拆分/人工审核”。
- 代表词从“任意词”改为“headword 或已验证有独立释义的词”。
- 选项状态从“点击即 FSRS”改为“只写事件 + 组状态”。
- 漏选从“一律不认识”改为“只记 missed，显式标记才写 FSRS”。
- 即时反馈从“全局”改为“练习模式”；测试模式两阶段提交。

**废弃：**

- 用连通分量当组（会把反义/不同词性合并）。
- 按中文释义字符串全量自动合并。
- 把一组词做成一张 FSRS 卡。
- 每次点击批量改写多个词的 FSRS。
- “每个词都能当代表”的无条件版本。
- 在线同义词库自动抓取（隐私/版权）。
- 905 组塞进 25 词/天计划。

**指标：**

- 组到期保持率。
- FSRS 完整性（选项点击不应改变 `word_states.due/stability`）。
- 覆盖率（可用组 / 总组；低于 30% 说明词书不匹配）。
- 主观负担（每组耗时、放弃率）。

**风险与对策：**

#### 5.10.3 合理性评估（逐条）

**第 1 条（不定项选择释义）——方向正确，是本方案最有价值的一处改动。**

- 现状 [StudyView.vue](../../frontend/src/views/StudyView.vue) 的三个自评键是纯主观输入；[FSRS 专题 §2.14](FSRS原理效果与优化清单.md) 已明确“FSRS 不负责评级是否真实”。改成客观题后，评级第一次有了可复核的依据。
- 对多义词，一次多选可同时覆盖多个义项，避免“义项 A 会了、义项 B 被当成会”（§5.4 的 C7）。
- 与旧结论不冲突：它仍然是“词义层”的测量，不改变“选项不作评分依据”的分离原则（§5.5.2）。

需要补三处：

1. **新词首见不能直接开考。** 现在 `intro` 是“你还记得吗”，答完才给详情。改成选择释义后，新词首见就是纯猜：4 选 1 基线 25%，猜中也给 Good 会虚增 stability。建议新词首见改为“先展示释义（学习步进）→ 立刻多选”，或保留“看释义”入口但不计分。
2. **评级要设上限。** 识别型测试（选择题）系统性高估记忆强度，与回忆型测试不等价。建议单道选择题最高只给 Good；Easy 只在“全对且 `response_ms` 低于阈值”或“连续第 2 次全对”时给。
3. **选项数要与义项数解耦**（见 D2）。

**第 2 条（等价组独立 + 单义代表词）——动机正确，但“单义”的判定口径是最大漏洞。**

动机在数据上成立：1,318 个词里有 545 个（41.4%）挂过 ≥2 种释义，`capricious` 挂 6 种、`volatile` 4 种、`mitigate` 4 种。这些词当代表词时，一次“对/错”并不能代表“这个词会不会”。

但“仅选择一个释义的单词做代表词”必须先回答“按什么算一个释义”：

- 按 `words.definition` 字符串切（`；;`）：899 / 905 = **99.3%** 的词都算单义 → 规则等于没写，`capricious`、`volatile` 照样当代表词。
- 按“释义图”（该词在所有等价行里挂过的不同释义）：只有 773 / 1,318 = 58.6% 单义；作为组代表时，905 组里只剩 **500 组（55.2%）** 有合格代表，**386 组（42.7%）** 连头词都不合格。

两个口径差 56 个百分点。建议：**代表词资格按“组内义项”判定**，调度单元用 `词×义项`（单义词天然只有一张卡），而不是“单词全局是否单义”；并对 405 个无单义成员的组给兜底（回退 headword、只练习不计分）。

**第 3 条（简化：题型收敛为两种）——合理，但要接受“组不再被调度”。**

- “代表词测试由单选覆盖”其实就是 `meaning_multi` 在 n=1 时的特例，题型统一是干净的；`QuizCard.vue` 的键盘 1–4、结果反馈、答错给答案都能复用。
- 代价：等价组从“可调度单元”降级为“题型”。旧 §5.5.6 的 Leitner、10–20 组/天、hub 限流都会失效，组覆盖率不再受控。
- 建议保留一个**最小组账本**（`last_seen` / `seen_count` / `status`），只做冷却与覆盖率统计，不参与评分。

**第 4 条（单词=顶点，释义=边）——直觉对，但图要建在“义项”上，不能直接建在释义字符串上。**

实测：895 个唯一无序等价对 → **470 个连通分量，最大 20 词**（与 §5.2 的结论一致）。这等价于已被否决的“按中文释义合并 + 连通分量”，会把反义与不同词性拉在一起（`mitigate` 分量含 `block`、`caustic` 分量混名词/动词）。

数学上也不严谨：同一对词可能共享多个义项（实测 288 对如此）→ 普通无向图不够，需要多重边或边标签；而连通具有传递性，会制造伪等价（A~B、B~C 推不出 A~C）。

修正：**二部图**——词顶点 + 义项顶点，边 = “该词具有该义项”；两词等价 = 共享同一义项顶点。等价组 = 该义项的邻居的一个**经审核子集**。这样既保留“相同释义连边”的直觉，又不做词-词闭包；义项块规模也可控（实测按释义聚合 767 块，最大 11 词）。

**第 5 条（等价对未必基于明确释义）——这个担心被数据证实，应升级为一等公民。**

1,183 条 (词对, 释义) 边里，**288 对（32.2%）** 挂着 ≥2 种释义。典型如 `indifferent → apathy`（词性错位）、`sanction → endorse, countenance`（“制裁，批准”自相矛盾）、`general → abstract`（松散等价）。所以“共享义项”算不出来，只能审核出来。建议把审核单元从“905 组”改成“895 对 / 1,183 条边”，优先审 288 对多释义的。

#### 5.10.6 修订后的设计（建议口径）

**题型（收敛为 2 种）**

| 题型 | 题干 | 选项 | 正确项数 | 写 FSRS |
|------|------|------|----------|---------|
| `meaning_multi` | 英文单词 + 音标/发音 | `n=1` 时 4 个；`n≥2` 时 `max(5, n+2)` 个义项，n = 目标义项数 | n（通常 1–3，最多 6） | 是（目标词） |
| `equiv_group` | 先做代表词的 `meaning_multi`，再给组选项 | 组内成员 + 干扰词 | 组内除代表词外的全部成员 | 仅代表词；选项词否 |

- 单义词即 `n = 1` 的特例：**4 个选项（3 错 1 对）**、1 个正确项，与“单选”完全同构，前端只需一个多选组件。
- 多义词 `n ≥ 2`：正确项为全部义项，选项数 `max(5, n+2)`（`n=2/3` 时为 5 个选项，`n=6` 时扩到 8 个），保证干扰项始终 ≥ 2 个。

**评分映射（不改 FSRS 算法，只改输入）**

| 表现 | Rating | 说明 |
|------|--------|------|
| 全对且用时短 / 连续第 2 次全对 | Easy | 可选，默认关闭 |
| 全对 | Good | 常规 |
| 部分正确（≥1 且 < n） | **Hard** | 首次启用 Hard，正好压缩识别型测试的虚高 |
| 全错 | Again | |

- FSRS 只认四档；方案 D 只改“怎么由答题得到这四档”。实现上 `scheduler.py` 的 `RESULT_TO_RATING` 增加 `partial → Rating.Hard` 即可，不改算法。
- 这也回答了“考虑重新设计 FSRS（先保留）”：**暂时不需要动算法**；等 `review_logs` 累计到几百条后再评估（见 FSRS 专题 §5.2.2）。

**代表词**

```text
候选 = 组内成员 ∩ 当前词书有词形 ∩ 该组义项下只有一张义项卡
若无候选 → 回退 headword 当代表，组标记 needs_review（只练习，不计分）
排除    → 仅作选项的词（无释义）、external 词
```

**选项词**

- 多义词优先；干扰项排除：同组词、与正确义项近义的词（用 `equivalence_edges` 做负向过滤）、与正确答案长度近似的词。
- 选项只放**单个义项**，不放整串释义（避免“长答案即正确答案”的长度偏置）。
- 同一个词的多个义项不得同时出现在同一题的干扰项里，否则等于教会用户“这词是多义词”。

**组测试定位**

- 不产生独立 `next_due`；由代表词的 FSRS 到期触发，或作为 `meaning_multi` 答对后的追加题。
- 组账本只记 `last_seen / seen_count / status`，用于 15 分钟冷却与“未覆盖组”报表。
- 选项词在被点击时**只写事件**，不写 `word_states`（沿用 §5.5.2 的分层）。

#### 5.10.7 数据模型（迁移 v4 修订）

> **2026-11-01 二次修订**：本节草案中的 `equivalence_edges`（词—词边）**已作废**，改由 §5.11.2 的 `senses` + `word_senses` 实现；`equiv_group_ledger` 改名 `sense_ledger`。表结构以 §5.11.2 为准，本节保留作为演进记录。

§3.6 的 4 张表改为“义项 + 边 + 账本”三件套；`synonym_groups` / `synonym_group_members` 降级为导入溯源表，不参与调度。

```sql
CREATE TABLE word_senses (                  -- 词 × 义项（二部图的一侧）
  id          BIGINT PRIMARY KEY AUTO_INCREMENT,
  book_id     BIGINT NOT NULL,
  word_id     BIGINT NOT NULL,
  sense_no    SMALLINT NOT NULL,            -- 1..n
  gloss       VARCHAR(200) NOT NULL,        -- 该义项的中文表述（单条，不拼整串）
  pos         VARCHAR(16) NULL,             -- v./n./adj.
  source      VARCHAR(16) NOT NULL DEFAULT 'manual',   -- manual/parsed/accepted
  status      VARCHAR(16) NOT NULL DEFAULT 'active',   -- active/needs_review/retired
  created_at  DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uq_sense_word_no (word_id, sense_no),
  KEY ix_sense_book (book_id),
  FOREIGN KEY (word_id) REFERENCES words(id) ON DELETE CASCADE
);

CREATE TABLE equivalence_edges (            -- 等价边：两个词共享同一个义项
  id          BIGINT PRIMARY KEY AUTO_INCREMENT,
  book_id     BIGINT NOT NULL,
  sense_id    BIGINT NOT NULL,
  a_word_id   BIGINT NOT NULL,
  b_word_id   BIGINT NOT NULL,
  a_sense_no  SMALLINT NULL,
  b_sense_no  SMALLINT NULL,
  source      VARCHAR(32) NOT NULL DEFAULT 'gre_equiv_2026',
  source_ref  VARCHAR(64) NULL,             -- 页码/天/行号，可追溯
  confidence  DECIMAL(4,3) NULL,
  status      VARCHAR(16) NOT NULL DEFAULT 'needs_review',  -- active/needs_review/rejected
  UNIQUE KEY uq_edge (sense_id, a_word_id, b_word_id),
  KEY ix_edge_book_status (book_id, status),
  KEY ix_edge_a (a_word_id), KEY ix_edge_b (b_word_id)
);

CREATE TABLE equiv_group_ledger (           -- 最小账本：只做冷却与覆盖率，不评分
  user_id     BIGINT NOT NULL,
  sense_id    BIGINT NOT NULL,
  last_seen   DATETIME NULL,
  seen_count  INT NOT NULL DEFAULT 0,
  correct_count INT NOT NULL DEFAULT 0,
  status      VARCHAR(16) NOT NULL DEFAULT 'active',
  PRIMARY KEY (user_id, sense_id),
  KEY ix_ledger_seen (user_id, last_seen)
);
```

说明：

- 二部图：`word_senses` 是义项节点，`equivalence_edges` 是“词具有该义项”的关联；两个词等价 = 共享 `sense_id`。
- 一条边只挂**一个**义项；同一对词若共享 2 个义项，就是 2 条边（实测有 288 对需要这样表示）。
- `status='needs_review'` 的边不进每日任务，只在审核页出现；这是 §5.5 “数据质量优先于覆盖率”的延续。
- 备份 v2 需同步：`word_senses`、`equivalence_edges`、`equiv_group_ledger`（见 §6.4）。

```text
E ⊆ W × S        (w, s) ∈ E  ⇔ 单词 w 具有义项 s
```

- **等价是推导关系，不是边**：`a ≡ b ⇔ ∃ s, (a,s) ∈ E ∧ (b,s) ∈ E`。所以库里只需要“词—义项”这一种边。
- **等价不可传递**：`a ≡ b`（义项 1）、`b ≡ c`（义项 2）推不出 `a ≡ c`。这正是二部图相对“词-词连通分量”的核心优势，也是 §5.5.1 否决按释义合并的全部理由。
- **等价组 = 星（star）**：义项 s 的全部邻居 `N(s) = {w | (w,s) ∈ E}` 就是一组同义词，例如 `N(缓解:v) = {mitigate, abate, alleviate, ameliorate, …}`。组不跨义项，天然不会把反义拉进来。

三条可直接用于实现的性质：

| 编号 | 性质 | 对产品的含义 |
|------|------|--------------|
| P1 | `deg(w) = #{s : (w,s) ∈ E}`；`deg(w) = 1` 的词是叶子 | 叶子不可能是两个义项之间的桥 |
| P2 | 删去所有 `deg ≥ 2` 的词后，图退化为互不相交的星 | **连通性完全由多义词提供**；没有多义词，图不可跨块遍历 |
| P3 | 全图连通 ⇔ 恰有一个分量 | 实测见 §5.11.5：常态是**碎片化星群**，不要设计“遍历全图”的流程 |

#### 5.11.2 数据库方案（迁移 v4）

**结论先说：二部图的最小实现只有两张表**（`senses` + `word_senses`），等价对是 JOIN 出来的，不单独存。

```sql
-- ① 义项顶点（右侧）
CREATE TABLE senses (
  id             BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  book_id        BIGINT UNSIGNED NOT NULL,
  label_zh       VARCHAR(120) NOT NULL,          -- 展示名：缓和
  definition_en  VARCHAR(400) NULL,              -- 词典释义：make less severe
  pos            ENUM('v','n','adj','adv','phrase') NOT NULL,
  domain         VARCHAR(32) NOT NULL DEFAULT 'general',  -- general / gre / ielts
  status         ENUM('active','needs_review','retired') NOT NULL DEFAULT 'needs_review',
  merged_into    BIGINT UNSIGNED NULL,           -- 义项合并：指向合并后的规范义项
  created_at     DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at     DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uq_sense (book_id, label_zh, pos),
  KEY ix_sense_status (book_id, status),
  CONSTRAINT fk_sense_book FOREIGN KEY (book_id) REFERENCES word_books(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- ② 词—义项（二部图的边）
CREATE TABLE word_senses (
  id          BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  book_id     BIGINT UNSIGNED NOT NULL,          -- 冗余，和 word_states 的做法一致
  word_id     BIGINT UNSIGNED NOT NULL,
  sense_id    BIGINT UNSIGNED NOT NULL,
  gloss_raw   VARCHAR(200) NULL,                 -- 该词自己的表述（缓和 / 减轻 / 减弱）
  sense_no    SMALLINT NULL,                     -- 该词第几个义项，仅用于展示排序
  status      ENUM('active','needs_review','rejected') NOT NULL DEFAULT 'needs_review',
  confidence  DECIMAL(4,3) NULL,
  evidence    VARCHAR(300) NULL,                 -- 判定依据：词典来源/义项编号
  created_at  DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uq_word_sense (word_id, sense_id),
  KEY ix_ws_sense (sense_id, status),            -- 取某义项的全部邻居
  KEY ix_ws_word  (word_id, status),             -- 取某词的全部义项（算度）
  KEY ix_ws_book  (book_id, status),
  CONSTRAINT fk_ws_word FOREIGN KEY (word_id) REFERENCES words(id) ON DELETE CASCADE,
  CONSTRAINT fk_ws_sense FOREIGN KEY (sense_id) REFERENCES senses(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- ③ 候选边（PDF / 其他词表给的是“假设”，不是事实；审核后才落成 ②）
CREATE TABLE equivalence_candidates (
  id            BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  book_id       BIGINT UNSIGNED NOT NULL,
  a_word_id     BIGINT UNSIGNED NOT NULL,
  b_word_id     BIGINT UNSIGNED NOT NULL,
  source        VARCHAR(32) NOT NULL,            -- gre_equiv_2026 / manual / wordnet
  source_ref    VARCHAR(64) NULL,                -- p12#row7，可追溯
  source_gloss  VARCHAR(200) NULL,               -- 原表给的释义（只作参考）
  status        ENUM('pending','accepted','rejected_pos','rejected_sense','needs_review')
                NOT NULL DEFAULT 'pending',
  shared_sense_id BIGINT UNSIGNED NULL,          -- accepted 时填：共享的义项顶点
  note          VARCHAR(300) NULL,
  decided_at    DATETIME NULL,
  UNIQUE KEY uq_cand (a_word_id, b_word_id, source),
  KEY ix_cand_book (book_id, status),
  KEY ix_cand_a (a_word_id), KEY ix_cand_b (b_word_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- ④ 最小组账本（沿用 §5.10.6：只做冷却与覆盖率，不评分）
CREATE TABLE sense_ledger (
  user_id     BIGINT UNSIGNED NOT NULL,
  sense_id    BIGINT UNSIGNED NOT NULL,
  last_seen   DATETIME NULL,
  seen_count  INT NOT NULL DEFAULT 0,
  correct_count INT NOT NULL DEFAULT 0,
  status      ENUM('active','retired') NOT NULL DEFAULT 'active',
  PRIMARY KEY (user_id, sense_id),
  KEY ix_ledger_seen (user_id, last_seen)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

三条建模约定（决定这张图会不会越建越乱）：

1. **一个义项只建一个顶点**：`senses.label_zh` 放规范名（如「缓解」），同一个意思的不同措辞（缓和 / 减轻 / 减弱 / 改善）放 `word_senses.gloss_raw`，**不要**因为措辞不同就新建顶点。
2. **词性进顶点主键**：`(label_zh, pos)` 唯一。`indifferent(adj)` 与 `apathy(n)` 即使意思相近，也必须是两个候选被 `rejected_pos` 拒掉，而不是被合并。
3. **合并要留痕**：人工把两个义项判为同一个时，用 `senses.merged_into` 指向规范义项，旧顶点置 `retired`，`word_senses` 不动——这样重跑审核仍可复现。

**为什么不建 `equivalence_edges`**：词与词之间的等价完全由图推导，多存一张表就多一份不一致风险（§5.10.7 的旧草案已按本节作废）。性能敏感时再物化，且必须标明“派生、可重建”：

```sql
-- 可选：物化等价对（派生表，可随时重建）
CREATE TABLE word_equiv_pairs (
  book_id BIGINT UNSIGNED NOT NULL,
  sense_id BIGINT UNSIGNED NOT NULL,
  a_word_id BIGINT UNSIGNED NOT NULL,   -- 恒有 a_word_id < b_word_id
  b_word_id BIGINT UNSIGNED NOT NULL,
  PRIMARY KEY (sense_id, a_word_id, b_word_id),
  KEY ix_pair_a (a_word_id), KEY ix_pair_b (b_word_id)
);

-- 重建语句（幂等：TRUNCATE 后 INSERT ... SELECT）
INSERT INTO word_equiv_pairs (book_id, sense_id, a_word_id, b_word_id)
SELECT a.book_id, a.sense_id, a.word_id, b.word_id
FROM word_senses a
JOIN word_senses b
  ON a.sense_id = b.sense_id AND a.word_id < b.word_id
WHERE a.status = 'active' AND b.status = 'active';
```

三条核心查询（其余都由它们组合）：

```sql
-- 1) 同义组：某义项的全部成员 = 一组等价词
SELECT w.id, w.spelling FROM word_senses ws
JOIN words w ON w.id = ws.word_id
WHERE ws.sense_id = ? AND ws.status = 'active';

-- 2) 某词的度（判断能否做代表词）：度=1 才是叶子
SELECT COUNT(*) FROM word_senses WHERE word_id = ? AND status = 'active';

-- 3) 某词的全部同义词（跨多个义项，用于多选干扰项/展示）
SELECT DISTINCT ws2.word_id FROM word_senses ws1
JOIN word_senses ws2 ON ws2.sense_id = ws1.sense_id AND ws2.word_id <> ws1.word_id
WHERE ws1.word_id = ? AND ws1.status = 'active' AND ws2.status = 'active';
```

迁移规则照 §3.4：**v4 只增表，不改既有表**；`synonym_groups*` 系列（§5.6 草案）不再实现，仅作为候选来源的历史记录保留在 `equivalence_candidates.source`。

#### 5.11.3 审核标准：拿“真实释义”判共享义项

> **2026-11-02 修订**：判定依据已升级为「真题答案 + 真实释义」双证据，见 §5.12.4。
> 本节保留“仅按释义”的判定链，作为**没有真题覆盖时的兜底**；真题给出的正向对优先级更高。

审核输入不是 PDF 的释义列（那一列描述的是**头词**，不是每个近义词），而是每个词自己的义项清单。来源优先级：

1. 词书 `words.definition`（用户自带，最贴近实际背诵内容）；
2. 本地导入的词典义项（离线，不联网，符合 §1.4 的非目标）；
3. 人工/模型标注（必须标 `source`，进审核队列，不直接 `active`）。

判定链（自上而下，任一步失败即拒绝）：

| 步 | 检查 | 失败结论 |
|----|------|----------|
| 1 | 两个词都有义项清单，且义项数 ≥ 1 | `needs_review`（数据不足，不猜） |
| 2 | 存在词性相同的义项对 | `rejected_pos`（词性错位） |
| 3 | 该义项对属于同一义项族（同一 `senses` 顶点） | `rejected_sense` |
| 4 | 两词在同一最小框架内可互换而不改变真值 | `rejected_sense`（上下位/整体部分/松散喻义） |
| 5 | 不是反义、不是同一词的不同词形 | `rejected_sense` |

实测出来的四类反例（都来自这份 PDF，`analysis/bipartite_audit_table.md`）：

| 类别 | 例子 | 处置 |
|------|------|------|
| 词性错位 | `indifferent(adj) ↔ apathy(n)`、`vitriolic(adj) ↔ opprobrium(n)` | `rejected_pos`，不进图 |
| 义项不同 | `curtail(缩减) ↔ mitigate(缓和)`、`arbitrary(武断) ↔ capricious(反复无常)`、`general(笼统) ↔ abstract(抽象)` | `rejected_sense` |
| 行内多义被误当组 | `obscure` 一行给了 `anonymous / opaque / obfuscate` 三个近义词，对应三个义项 | 审核后变成三条边、三个星，**三个近义词之间两两不等价** |
| 词性混合行 | `sanction → endorse, countenance`，释义“制裁，批准”自相矛盾 | 只接受 `approve` 义项的那条边 |

> **义项族的维护**是审核能否规模化的关键。`缓和 / 减轻 / 减弱 / 缩减` 是不是同一个义项？`笼统 / 抽象` 是不是同一个？这些判断必须落到一张受控词表（`senses`）上，由人工确认一次，之后按表归并；不能靠字符串相似度自动合并。

#### 5.11.4 可建性实测（58 词样本，2026-11-01）

样本覆盖四个典型区：缓解族、尖刻族、多变族、易误判族（词性错位/自指反义/多义桥）。每个词按真实词典义项标注（词性 + 英文释义 + 中文义项 + 义项族）。

| 样本词 | 58 |
| PDF 在样本词之间给出的候选对 | 85 |
| 审核通过 | 56 |
| 因义项不同被否 | 28 |
| 因词性错位被否 | 1 |
| **被否比例** | **29 / 85 = 34.1%** |

审核后建成的图：

| 指标 | 审核后的二部图 | 对照：照抄 PDF 的图 |
|------|----------------|----------------------|
| 词顶点（进入图的） | 45 | 57 |
| 义项顶点 | 13 | 26 |

#### 5.11.5 单义词与“能否遍历全图”

**先纠一个定义**：这里的“单义”必须按**图内度**算，不是按词典义项数算。

| 口径 | 样本中的数量 | 能否做代表词 |
|------|--------------|--------------|
| 词典只有 1 个义项 | 25 / 45 | 可以，但会漏掉 19 个词 |
| **图内度 = 1**（只挂 1 个等价义项） | **44 / 45（98%）** | 可以，覆盖率 100% |
| 词典多义但图内度 = 1 | 19 个（`check`、`sound`、`hail`、`sanction` 等） | 可以；它们只是“在别的义项上没有同义伙伴” |

原因很直接：一条等价边只取一个义项，而一个词通常只在少数义项上有同义伙伴。所以**“多义词干扰记忆”这个担忧，在按真实释义重建后基本消失了**——它原来主要来自 PDF 用同一列释义描述**头词**：`capricious` 在 7 个组里被贴上 5 种释义（随意的 / 冲动的 / 善变的 / 难以预测的 / 多才多艺的），但那些释义是在描述各组的头词，它自己只有“反复无常”一个义项。

**遍历性实测**（从每个度=1 的词做 BFS）：

| 起点 | 可达词 | 可达义项 |
|------|--------|----------|
| 大多数叶子（`acclaim`、`bound`、`check`、`hail`、`sound` …） | 2 / 45 | 1 / 13 |
| 处在含“桥”的分量里的叶子（`abstruse`、`anonymous`、`arcane`） | 9 / 45 | 3 / 13 |
| 唯一的桥 `obscure`（度 = 3：不出名 / 费解 / 遮掩） | 9 / 45 | 3 / 13 |
| （全图合计，**没有任何起点可达**） | 45 / 45 | 13 / 13 |

**结论（重要）：**

1. **用单义词遍历全图，不可能**，而且不需要。叶子只能覆盖自己所属的义项星；能跨块的只有 `deg ≥ 2` 的词（性质 P2）。实测最大分量只有 9/45 = 20%。
2. **正确的目标是“逐块覆盖”，不是“全图连通”**：13 个义项块全部有度=1 的成员，块覆盖率 100%，每个词都能被它所属的星覆盖。
3. **多义词不是负担，是唯一的跨块通道**：`obscure` 一个词就把“不出名/费解/遮掩”三颗星缝在一起。所以方案 D 里“多义词只做选项词”要限定为**不参与等价组的代表词**，而不是“永不生长义项卡”——否则桥永远走不通，跨义项的联想也就断了。
4. **不要做“图遍历进度条”**：图是碎片化的，进度应按“已覆盖的义项块 / 总块数”统计（§5.10.6 的组账本正好承担这个指标）。

### 5.12 真题库（2026-11-02）：目录、格式与导入流水线

> **本节的定位**：把“真题 + 答案”变成一等证据。§5.11 只靠释义审核时，58 词样本里 34% 的候选对判“不成立”；
> 真题答案能给这些词对提供**正向**证据（GRE 六选二的两个正确选项天然等价），再用释义确定它们共享哪个义项。
> 原则：**真题定“谁和谁等价”，释义定“在哪个义项上等价”**。

#### 5.12.1 存放目录

#### 5.12.2 文件格式

| 列 | 必填 | 说明 |
|----|------|------|
| `题号` | 是 | 同一 session 内唯一；多套卷拼在一个文件时写成 `S1-Q3` |
| `答案A` | 是 | 单词，或选项字母 `A`–`F` |
| `答案B` | 是 | 同上；两个答案顺序无关，脚本规范成 `a < b` |
| `备注` | 否 | 争议题、OCR 问题等 |

- 填**字母**时必须同时提供 `questions.pdf`，导入脚本用 PDF 解析出的选项表做映射；纯单词答案不需要 PDF。
- 一个 `.xlsx` 一个 sheet（优先读 `answers`，没有则读第一张）；不要合并单元格、不要 `.xls`/`.csv`。

**题面 PDF**：文本层可复制（扫描件需先 OCR）；题号清晰；每题 6 个选项标 A–F。解析产物写到 `derived/items.json`：

```json
{
  "session": "2026-10-zhangwei-se",
  "items": [
    { "no": "1", "stem": "……", "options": { "A": "mitigate", "B": "abate", "C": "…", "D": "…", "E": "…", "F": "…" } }
  ]
}
```

**PDF 解析与答案导入是两步、解耦的**：前者产出 `items.json`，后者只消费它。这样换 OCR/换解析器不影响答案处理，也允许先只交“纯单词答案”跑通全流程。

#### 5.12.3 导入流水线与可执行脚本

```text
① 放进 private/exams/inbox/
② python scripts/check_exam_answers.py <session>/answers.xlsx     # 列名/重复题号/字母vs单词
③ （可选）解析题面 → <session>/derived/items.json
④ python scripts/import_exam.py <session>                          # 产出 answers.json / edges.json / manifest.json
⑤ 审核入库：edges.json 的每条边 → equivalence_candidates（evidence=exam, trust=strong）
```

脚本现状：

| 脚本 | 作用 | 依赖 |
|------|------|------|
| [check_exam_answers.py](../../scripts/check_exam_answers.py) | 只校验格式，提前暴露列名错、题号重复、字母答案缺 PDF | 仅 openpyxl |
| [import_exam.py](../../scripts/import_exam.py) | Excel → 规范化答案 + 等价边 + manifest（含 sha256） | 仅 openpyxl |
| （待写）`parse_exam_pdf.py` | PDF → `items.json` | pymupdf（届时再加） |

依赖单独放 [requirements-import.txt](../../backend/requirements-import.txt)，**不进服务端运行时**；导入是本地脚本，不做成 HTTP 接口（§1.4 不做云同步，也没必要把版权文件传进服务）。

#### 5.12.4 证据分级与判定（取代“只按释义判定”）

| 证据 | 来源 | 可信度 | 作用 |
|------|------|--------|------|
| **真题答案** | `answers.xlsx` 的同一题两个答案 | **strong** | 判定“这两个词等价”，并可反查题号 |
| 词典/词书释义 | `words.definition`、本地词典 | medium | 判定“在哪个义项上等价”（建 `senses` 顶点） |
| 第三方等价词表 | PDF 905 行 | weak | 只作候选来源，必须被前两者之一确认 |

判定规则：

```text
真题对 + 释义能定出共享义项   → accepted（evidence=exam, sense_id=…）
真题对 + 释义判为不同义项     → needs_review（exam_dictionary_conflict，人工裁决）
真题对 + 词书里没有该词       → accepted，但 word_id 为空（external，只做展示/选项）
只有词表对 + 释义支持          → accepted（evidence=dictionary, trust=medium）
只有词表对 + 释义不支持        → rejected_sense（§5.11.4 的 34% 正是这一类）
只有词表对 + 没有释义          → needs_review（不猜）
```

这直接回答了上一轮的遗留问题：**§5.11.4 里被否掉的 29 对，不是“永久作废”，而是降级为“待真题确认”**。真题一旦给出正向证据，它们会被重新激活，并由释义补上义项归属；若真题与释义仍然冲突，才进人工队列。

### 5.13 FSRS 的适用范围与“义项级调度”（2026-11-02）

> **本节回答两个问题**：① 现在 FSRS 到底管什么；② 二部图建好之后，要不要在“同义替换词组”里也引入 FSRS。
> 结论：**要引入，但粒度是“义项”而不是“词组”**——因为在二部图下，一个同义替换组就是一颗义项星，两者是一回事。

#### 5.13.1 现状确认：FSRS 目前只服务“词形卡”

| 项 | 现状（v1.0.0） |
|----|----------------|
| 调度单元 | `word_states`：**一个词一张卡**（`word_id` UNIQUE） |
| 取卡入口 | `GET /api/study/today`：`stability IS NOT NULL AND due <= now` |
| 写评级入口 | `POST /api/study/answer` → `RESULT_TO_RATING` → `apply_answer` |
| 评级来源 | 自评三键 / 四选一 / 挖空 |
| 实际用到的档位 | Again、Good、Easy（Hard 未启用） |
| 复习池排序 | `due ASC, lapses DESC` |

也就是说：**FSRS 现在只回答“这个词的拼写+释义记住了吗”，不回答“这个义项的同义替换掌握了吗”。**

#### 5.13.2 二部图引出的三个新问题

1. **卡的身份**：调度单元是词、义项，还是“词×义项”？
2. **一次复习覆盖几个词**：一个义项星有 2–7 个词，点一次“确定”该给谁记分？
3. **多义污染**：`mitigate` 有“缓和”和“调停”两个义项，在 A 义项答对，会不会被当成 B 义项也会？

旧方案 C 的答案是“不做，组不建 FSRS”（§5.5.1）；方案 D 的答案是“多义词只做选项词、不写 FSRS”（§5.10.4 D3）。
这两种处理都回避了问题，代价是**多义词永远停在 `new`**。

#### 5.13.3 四种候选粒度

| 方案 | 卡是什么 | 卡数（当前数据） | 优点 | 缺点 |
|------|----------|------------------|------|------|
| **A 词级**（现状） | 词 | 1,804 | 实现最简单 | 多义词无法区分（旧 C7）；义项星里同一个词会被反复考 |
| **B 义项级**（推荐） | 义项（sense） | 1,150 | 与二部图同构；多义自动拆卡；一张卡 = 一组同义替换 | 依赖义项审核；无同义伙伴的义项没有卡 |
| C 词×义项 | (word, sense) | ≈2,300 | 粒度最细 | 卡数翻倍；星内高度相关，同一事实被记多次 |
| D 词级 + 组账本 | 词 + 组 | 1,804 + 1,150 | 保留现状 | 两套状态并存，证据分裂（旧 C3） |

#### 5.13.4 推荐方案 B：卡 = 义项（= 一组同义替换）

**核心理由：在二部图里，“同义替换词组”就是义项星 `N(s)`。**
所以“给同义词组引入 FSRS”和“给义项建 FSRS 卡”是同一件事，不存在“另行设计一套组调度”的问题。

| 维度 | 方案 B 的答案 |
|------|----------------|
| 卡面 | 义项 `s`：`label_zh` + 英文释义 |
| 卡背 | `N(s)`：该义项下的全部同义词（2–7 个） |
| 题型 | 给一个代表词 + 干扰项，选出同义替换（即 §5.10.6 的 `equiv_group`） |
| 一次作答 | 对整个义项星评一次分，写一张卡 |
| 多义词 | 天然拆成多张卡（`mitigate` 的“缓和”和“调停”各一张） |
| 复习量 | 1,150 张卡 < 1,804 个词，且每张卡对应一个可考的事实 |

**与方案 D 的关系**：B **修正**了 D3——多义词不再“永久停在 new”，它在每个有同义伙伴的义项上都会生成卡；只是它不当等价组里的“代表词”而已。

#### 5.13.5 两类卡的分工（避免重复计分）

```text
义项有同义伙伴（deg(s) ≥ 2）  → sense 卡（FSRS）→ 题型 equiv_group（同义替换多选）
义项没有同义伙伴（deg(s) = 1） → 词级卡（FSRS）→ 题型 meaning_multi（不定项选释义）
```

- 一个词若同时命中，两条线各自独立记分：词级卡考“释义广度”，义项卡考“同义网络”。两者不是同一次记忆事件，**不合并评级**（沿用 §5.5.2 的分层原则）。
- 发音/拼写若以后要练，仍挂在词级卡上，不进义项卡。

#### 5.13.6 评分映射（不改 FSRS 算法）

沿用 §5.10.6 的口径，只把“输入”接到义项卡上：

| 表现 | Rating |
|------|--------|
| 星内全部选中、无漏选、无错选 | Good |
| 选中一部分（≥1 且不全） | **Hard** |
| 全错 / 选了星外词 | Again |
| 连续第 2 次全对且用时短 | Easy（默认关闭） |

`fsrs==6.3.2` 本身不用改；新增 `sense_states` 表，字段与 `word_states` 一致（`state/step/stability/difficulty/reps/lapses/due/last_review/status`），维护逻辑直接复用 `scheduler.py` 的 `apply_answer`。

#### 5.13.7 风险与对策

| 风险 | 说明 | 对策 |
|------|------|------|
| 冷启动 | 义项卡第一次出现时用户还没“学过”这个义项 | 首见先展示卡背（义项 + 成员），再考 |
| 星大小不均 | 2 词星与 7 词星难度差异大 | 让 FSRS 的 `D` 吸收；必要时按星大小给 Hard |
| 同词多卡互相“顺带复习” | 复习“缓和”时看到 `mitigate`，可能顺带巩固“调停” | 接受：不同义项的证据本就互相干扰，这正是分卡的理由 |
| 卡数膨胀 | 每新增一个词对就多一张卡 | 设上限（如 100 张/天），并优先高 `lapses` 的星 |
| 义项审核滞后 | `needs_review` 的义项不能建卡 | 只给 `active` 义项建卡，审核队列先用 `meaning_multi` 兜底 |

#### 5.13.8 实施顺序

1. 把 1,150 对写进 `senses` / `word_senses`（占位义项，`needs_review`）。
2. 审核过的义项 → `active` → 生成 sense 卡。
3. 迁移新增 `sense_states`（结构照抄 `word_states`）。
4. 题型接 `equiv_group`，评分走 §5.13.6 的映射。
5. 观察“义项卡到期正确率”是否接近 `desired_retention`；若显著偏低，说明评级偏乐观，下调映射。

> **一句话**：FSRS 不是“要不在词组里用”，而是——**二部图的义项顶点就是天然的卡；组级 FSRS 只是义项级 FSRS 的另一种说法。**

### 5.14 拆义项队列（定义与流程）

> 前文多次提到“需拆义项的 361 个词”，这里给出它的准确定义、产生原因和操作流程。

#### 5.14.1 它是什么

**真题词对只说明“这两个词等价”，没说“在哪个义项上等价”。**
当一个词只出现在 1 个词对里，它的义项没有歧义（一条边 = 一个义项），直接建一个义项顶点即可。
当**一个词出现在 ≥2 个词对里**，就必须判断：这些词对用的是同一个义项，还是不同义项？

这个“待判定清单”就是**拆义项队列**：

```text
词 w 连了 k 个词对（k ≥ 2）
  ├─ 判定「同一个义项」→ 这 k 个词对合并成一个义项星
  └─ 判定「不同义项」  → 拆成 m 个义项顶点（m ≤ k），每条边挂各自的 sense_id
```

**为什么不是所有词都进队列**：当前 1,804 个词里，1,443 个（80%）只连 1 个词对，没有歧义；**只有 361 个词需要判定**。

#### 5.14.2 为什么必须做（反例）

| 词 | 连的词对 | 问题 |
|----|----------|------|
| `manifest` | patent×3、reveal×3、self-evident×2、evident、obvious | **adj 明显的**（evident / obvious / patent / self-evident）与 **v 显示**（reveal）是两个义项；不拆就会产出 `obvious ~ manifest ~ reveal` 的错误同义组 |
| `uncertain` | contingent×2、precarious×2、tenuous×2、indeterminate、questionable | “取决于”（contingent）、“危险”（precarious）、“薄弱”（tenuous）三种意思被缝在一起 → 就是 `loose ~ parlous` 那类误并 |
| `commonplace` | unremarkable×3、pervasive×2、unexceptional、ordinary、mundane | “平凡/不出众”与“普遍/遍布”（pervasive）是否同一义项，需要人判 |

#### 5.14.3 队列条目的字段

| 字段 | 说明 |
|------|------|
| `word` | 待判定的词 |
| `degree` | 连了几个词对（优先处理 3–6 的） |
| `pairs` | 它参与的全部词对 + 出处（哪套卷、第几题） |
| `proposal` | 机器初判：基于《机经词》释义的自动聚类结果 |
| `decision` | 人工结论：`merged`（同一义项）/ `split`（拆成 N 个义项） |
| `status` | `pending` / `in_review` / `done` |

#### 5.14.4 处理流程

> **2026-11-02 修订**：本节原先写的是“人工判定 361 个词”。经复核，这个说法过于保守。
> 正确的分工是 **机器全量出方案 + 人只审分歧**，见 §5.14.6。

```text
① 机器第一层（结构）：按「搭档词性」自动拆分
   —— 同题两个正确答案必须同词性，所以搭档的词性就是这条边的词性。
   实测：361 个枢纽词里，24 个可以被这一层直接拆开（manifest → adj/v、censure → v/n …）
② 机器第二层（语义）：用机经词释义 + 同题题干上下文聚类，把同词性的邻居再分堆
③ 机器第三层（判定）：模型逐词给出拆分方案 + 置信度（高/中/低）
④ 人只审：低置信条目 + 按 10% 抽检高置信条目
⑤ 每个词产出一个 sense 划分；写入 word_senses（边 → sense_id）
⑥ 合并的两个 sense 记 merged_into，保留痕迹、可回滚
```

- **与“边审核”的区别**：§5.12.4 的边审核判“这条边成不成立”；拆义项判“这条边挂在哪个义项上”。两者都要，但问题不同。
- **没进队列的词对**（1,443 条叶子边）不需要人工，直接自动成为 2 词义项星。
- **量级**：361 个词；其中 337 个词的邻居词性单一（冲突只在语义层），24 个可由结构直接判定。人的实际工作量取决于第三层的置信度分布，预计几十条量级，而不是 361 条。

#### 5.14.5 为什么它决定后续一切

| 下游 | 依赖关系 |
|------|----------|
| 图结构 | 决定连通分量的形状与数量 |
| 义项卡数量（§5.13） | 拆得越细卡越多；合并得越粗卡越少 |
| 出题正确性 | 不拆就会产出 `loose ~ parlous` 这类错误同义组 |
| 覆盖率统计 | 义项星的大小直接决定“可用义项 / 总义项” |

#### 5.14.6 机器能走多远：三层自动判定 + 只审分歧
**为什么不是“必须人工”**：拆义项的判定依据大部分是可计算的——

| 层 | 判据 | 机器能做到什么 | 实测/预期 |
|----|------|----------------|-----------|
| ① 结构 | **搭档（同题另一个正确答案）的词性** | 同题两答案必须同词性，所以搭档词性 = 这条边的词性；一个词若在不同词对里搭档词性不同，必然是不同义项 | 361 个枢纽词中 **24 个可自动拆开**（`manifest` adj/v、`censure` v/n、`pervasive` adj/n…） |
| ② 语义 | 机经词释义（覆盖 45%）+ 同题题干语境 + 邻居的语义聚类 | 同词性且释义高度重合的邻居并成一堆；释义互斥的分开 | 337 个词性单一的枢纽词里，多数邻居本就语义接近（如 `ubiquitous / omnipresent / prevalent`） |
| ③ 判定 | 模型读「枢纽词 + 全部邻居 + 原题题干」 | 直接给出拆分方案与置信度 | 与人工判断的重合度需抽样验证 |

**真正只有人能做的**：拍板低置信条目。典型是“同词性、语义相邻但不重合”的边界，如 `commonplace ~ pervasive`（普遍）与 `commonplace ~ mundane`（平凡）——机器可以给出两个方案并标注不确定，但不该单方面定。

**因此人的工作量 = 低置信条目 + 10% 抽检**，而不是 361 条全量。

**四项可验证机制**（防止模型判错被放大）：

1. **置信度分档**：高 → 自动通过；中 → 抽检；低 → 人工必看。
2. **抽样复核**：每次跑完抽 10% 高置信条目人工比对，错误率 > 5% 就整批降级复审。
3. **可回滚**：所有拆分/合并写 `merged_into` + 审核日志，一条命令可还原。
4. **反向验证**：上线后看“义项卡到期正确率”。若某个义项星显著低于其他（如 < 60%），大概率是拆错或并错了，自动回到队列。

> 一句话：**机器全量出方案，人只做“否决”而不是“重做”。** 361 条不需要人工逐条过，但人保留最终的否决权。

#### 5.14.7 裁决归档（论文素材，代替系统级操作日志）

本阶段不做 `sense_audit_logs` 表（代码改动），改用**归档制**留痕：每一轮人工裁决产出一个带时间戳的目录。

```text
docs/audit/<YYYY-MM-DD>-<轮次>/
├── manifest.json          归档时间、操作人、每个文件的 SHA-256、统计、分歧明细
├── review_decisions.json  逐条裁决（原样）
├── review_queue_final.csv 复核表快照

```

- 生成脚本：`tools/archive_review.py`（读 `analysis/review_decisions.json` → 写归档目录）。

## 6. API 设计

### 6.1 通用约定

- 前缀 `/api`；JSON；Cookie 会话鉴权；未登录 401。
- 资源归属校验；跨账号统一 404。
- 参数校验失败 422；请求体/文件过大 413；限流 429 + `Retry-After`。
- 分页参数 `page/page_size`；`page_size` 上限 100。
- 错误响应包含可读中文 `detail`；前端统一拦截提示。
- 所有写接口幂等性要求：组提交按 `group_id + attempt_id` 可重试（规划）。

> **2026-11-01 更新**：本节是方案 C 的接口；方案 D（§5.10.8）把它收敛为 `meaning_multi` + `equiv_group` 两种题型，
> 组不再有独立 `start/rep-answer/submit` 三段式（代表词释义测试即 `meaning_multi`）。按方案 D 实现时以 §5.10.8 为准。

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/synonym-groups/today?limit=` | 今日组计划（按覆盖/到期/冷却过滤） |
| GET | `/api/synonym-groups?book_id=&status=&page=` | 组列表与覆盖率 |
| POST | `/api/synonym-groups/{id}/start` | 选代表词，返回代表词与释义；不返回全部答案 |
| POST | `/api/synonym-groups/{id}/rep-answer` | `{result: known\|unknown, response_ms}`；`known` 时响应带混合选项，`unknown` 时返回 `reveal` |
| POST | `/api/synonym-groups/{id}/submit` | `{attempt_id, selected: [], uncertain: [], response_ms}`；服务端判分 |
| GET | `/api/synonym-groups/stats` | 组准确率、覆盖率、到期数 |
| GET | `/api/synonym-groups/confusions` | 易混对列表（P3） |
| POST | `/api/synonym-groups/import` | 导入本地组 JSON（可选；大小/数量限制） |

关键约束：

- **服务端判分**：不下发 `answer_key`；前端只提交选择，服务端返回对错/漏选。
- `start` 只返回代表词与其释义；`rep-answer=known` 时在同一响应下发混合选项，避免提前泄露，也避免单独拉取选项绕过自评。
- `submit` 幂等：同一 `group_id + attempt_id` 重复提交返回同一结果。
- 组归属按 `user_id` 校验；`book_id` 只影响可关联成员。
- 导入 JSON 不提交到仓库；本地脚本优先。

### 6.4 备份 v2

- 新增：`synonym_groups/members/states`；`synonym_events` 可选。
- 兼容：`SUPPORTED_VERSIONS = {1, 2}`；导出写 2；导入同时接受 1/2。
- 理由：旧版本遇到含组数据的新备份应明确拒绝，而不是静默丢弃。
- 备份包含组定义时，提醒用户其中可能含第三方词表内容，不要公开分享。

### 6.5 错误与状态码

| 场景 | HTTP | 说明 |
|------|------|------|
| 未登录/会话失效 | 401 | 前端跳登录 |
| 资源不存在/非本人 | 404 | 不泄露存在性 |
| 参数/格式错误 | 422 | Pydantic/自定义校验 |
| 业务冲突（同名单词） | 409 | 如词表纠错 |
| 文件过大 | 413 | 上传/导入 |
| 限流 | 429 | `Retry-After` |
| 数据库不可用 | 503 | `/api/health` |
| 组已完成/过期 | 409 | 重新取今日计划 |

## 8. 安全、隐私与数据管理

### 8.1 账号与会话

- 密码：PBKDF2-SHA256，16 字节随机盐，260,000 次迭代；不存明文。
- 会话：30 天 HttpOnly Cookie（`SameSite=Lax`）；服务端只存 token SHA-256。
- 改密：吊销该账号全部会话，需重新登录。
- 注销：再次输入密码，物理删除账号及全部数据，不可恢复。
- 登录/注册/改密：进程内滑动窗口限流；多 worker 需换共享存储。

### 8.2 数据隔离

- 所有业务 API 通过 `user_id` 过滤；词书/单词/状态/流水/设置均按账号隔离。
- 跨账号访问返回 404，不泄露存在性。
- 当前词书必须属于当前用户；删除当前词书自动回退。

### 8.3 上传与导入

- 词书：`.md/.markdown/.txt`；默认 10 MB、20,000 词；字段超长截断。
- 备份：`.json`；默认 50 MB；校验格式/版本/词书数/单词数/流水数。
- 组数据：本地 JSON；限制组数/成员数；只允许当前用户导入。
- **真题（§5.12）**：**不走 HTTP 上传**。PDF/Excel 放在 `private/exams/<session-id>/`，由 `scripts/check_exam_answers.py` 与 `scripts/import_exam.py` 在本地转成 JSON；服务端只消费派生出的结构化数据（此时才需要“只允许当前用户导入”的校验）。理由：版权文件不应经过 Web 服务，也不该出现在备份或日志里。
- 服务端不信任前端校验；所有上限在 API 层再校验。

### 8.4 隐私与联网

- 不包含遥测、统计 SDK、崩溃上报、广告。
- 数据只存本机 MySQL；备份由用户保管。
- 联网仅：
  - 浏览器 TTS（可能由系统/浏览器决定是否云端）；
  - 没有英文语音时请求 `dict.youdao.com` 播放公开音频；
  - 组模块不联网；本地 PDF/JSON 导入。
- 服务只监听 `127.0.0.1`；不要暴露公网；`COOKIE_SECURE=false` 仅本地 HTTP 默认。

### 8.5 删除、备份与恢复

- 删除词书：物理删除并级联；当前词书回退。
- 重置进度：删除该词书流水、重置 `word_states`，保留单词。
- 备份：合并导入；同名词书改名；不覆盖现有数据。
- 组数据备份 v2：见 §6.4；恢复时按 `group_key` 合并。

### 8.6 第三方内容与版权

- 仓库不分发 GRE PDF、机经词书、提取脚本；`sample/` 只放自编示例。
- 组模块只提供“导入自己的资料”；界面注明来源；生成的 JSON/数据库不提交仓库。
- Open English WordNet 若使用，需遵守 CC BY 4.0 + WordNet License 并署名；SynoCN/Chinese-Synonyms 无许可证，不内置。

- 发布清单：版本一致、CHANGELOG、无密钥/无第三方资料、测试全绿、冒烟、exe/源码包 SHA-256。
- 已知限制：仅 Windows 打包、需要 MySQL 8、exe 未签名、限流单进程、备份合并导入。

### 9.4 新模块必测用例

1. 二元组（668 组典型）。
2. 7 个词的组（`versatile`）：6 个真选项 + 干扰项，卡片上限 9；同时是问题组，需审核/拆分。
3. 多义行（`obscure`、`sanction`）。
4. 短语行（`insulated from`）。
5. 只做近义词的词（`opprobrium`）做选项。
6. 词书缺成员（组内只有 1 个可关联词）。
7. 全组已熟知（应退役）。
8. 熟知词做干扰项且被漏选（不应写 FSRS）。
9. 重复/互逆对（不应重复计分）。
10. 词性错位组（允许“算我对”）。
11. 组提交幂等（重复提交返回同一结果）。
12. 迁移 v4：全新库/旧库升级/重复运行。
13. 备份 v2：导出→导入→组状态一致；v1 旧备份可导入。

方案 D（§5.10）追加用例：

14. `meaning_multi` 单选退化：单义词 n=1，恰好 4 个选项、1 个正确项。
15. 多义 n>2：`capricious`（6 个义项）必须能出题（选项数 `max(5, n+2)`），并断言不会出现“正确项多于选项”。
16. 部分正确映射：选 2/3 → `Rating.Hard`，且 `word_states.difficulty` 上升、`reps` 不重置。
17. 全错 → `Again`；全对 → `Good`；Easy 默认关闭（断言不会出现 `Rating.Easy`）。
18. 选项词点击不写 FSRS：组题提交后断言被点击的选项词 `word_states` 完全不变。
19. 二部图：一对词共享 2 个义项时必须生成 2 条边，且两条边可分别审核。
20. `needs_review` 边不进每日任务；`external` 词（无释义）不能当代表词。
21. 干扰项守卫：干扰项所属词若与目标词在同一 `sense_id` 下，必须被排除（避免一题多解）。
22. 单义判定口径一致性：同一词书两次导入，`word_senses` 与单义/多义标记完全一致。

### 9.5 性能

- 今日任务一次预取候选池 + `selectinload`，40 词查询数 ≤ 15。
- 组列表/今日组一次查询取组 + 成员 + 状态，避免 N+1。
- 905 组规模下，今日组只取 10–20 个；组详情按需加载。
- 统计按月/按天聚合，避免全表扫描。

### 10.2 研究结论

- Tinkham（1993, 1997）：按语义场成组呈现新词可能互相干扰（[ERIC 文献片段](https://files.eric.ed.gov/fulltext/ED460643.pdf)）。
- Erten & Tekin（2008）：课堂研究未复现该干扰，配合显式辨析时可能有利（[Semantic Scholar](https://www.semanticscholar.org/paper/Effects-on-vocabulary-acquisition-of-presenting-new-Erten-Tekin/03ba875353f58ebf7a9b1eb99c9cae45082c41f3)）。
- Kornell & Bjork（2008）：交错（interleaving）提升易混类别区分（[PubMed 18578849](https://europepmc.org/article/MED/18578849)）。

结论：**先各自建立词义，再做对比；练习可以分组，调度不能分组；错因要留痕。**

### 10.4 设计原则（最终版）

1. **调度单位是词**；组关系是额外练习层。
2. **组练习独立于 FSRS**；组状态用简单 Leitner。
3. **判分必须有依据**：精确/义项/显式近义词表/用户确认；模型只做兜底。
4. **测试模式两阶段**；即时反馈只用于练习。
5. **错选/漏选留痕**，但不自动改写词义状态。
6. **数据来自用户词书与本地导入**；不内置来源不明的词库。
7. **先小规模人工审核，再批量导入**；数据质量优先于覆盖率。
